HexStrike AI: convertir a Claude en un pentester real dentro de Claude Desktop con MCP

Fuente: «Claude AI as a Pentester? Setting up HexStrike-AI MCP on Kali Linux» · ver el video original

Resumen

HexStrike AI convierte la pregunta "¿y si le digo a Claude que hackee un sitio y Claude realmente lo haga?" en una herramienta concreta. Es un framework ofensivo de seguridad open source basado en MCP (Model Context Protocol) que tiende el puente entre la IA y las herramientas reales de ciberseguridad instaladas en el sistema: el agente deja de razonar en abstracto y pasa a ejecutar comandos de pentesting de verdad.

El arsenal que expone al modelo es amplio: gestión de más de 150 herramientas de seguridad distribuidas en categorías que cubren reconocimiento de red, testing de seguridad de aplicaciones web, seguridad de autenticación y contraseñas, análisis binario, seguridad de contenedores, herramientas de CTF y forense, bug bounty, y sistemas operativos y arsenal. A eso se suman más de 12 agentes de IA especializados que manejan optimización y automatización.

Instalación sobre Kali Linux con Claude Desktop

El despliegue sigue un camino corto y reproducible. Primero se clona el repositorio y se copia el comando de instalación en la terminal de Kali. Luego se crea y activa un entorno virtual de Python, y se instalan las dependencias con el archivo de requisitos, un proceso que toma unos minutos.

La conexión con el modelo se hace por MCP: desde la página de GitHub se copia el bloque de configuración correspondiente al asistente elegido —en la demo, Claude—, se abre Claude Desktop, y en Settings → Developer Settings → Edit Config se pega la configuración en el archivo, ajustando la ruta al directorio donde se clonó HexStrike. Tras guardar, hay que cerrar Claude Desktop por completo, levantar el servidor de HexStrike en la terminal y reiniciar el asistente. La verificación es directa: en Developer Settings aparece el servidor MCP como running, y un prompt de health check confirma el estado healthy e informa qué herramientas faltan en el sistema —conviene instalarlas todas para aprovechar el framework.

Prueba 1: resolver un lab de PortSwigger en minutos

La primera prueba fue resolver un laboratorio de PortSwigger pasándole el enlace y la instrucción de resolverlo. El agente pidió permisos para ejecutar herramientas a lo largo del proceso —hay que concederlos— y completó el lab mostrando el payload inyectado en la query. El tiempo es el argumento de venta: a mano, ese lab lleva entre 10 y 15 minutos; HexStrike lo resolvió en unos pocos.

Prueba 2: del escaneo al root shell

La segunda prueba fue ofensiva contra una IP objetivo: encontrar vulnerabilidades en su puerto FTP. El agente escaneó todos los puertos con varias herramientas, analizó la superficie y reportó una vulnerabilidad de backdoor en el FTP además de hallazgos de severidad alta y crítica en otros puertos y en el sistema. La interfaz ofrece un botón de explotación directa: un clic y el proceso arranca, con el log de shell y el detalle de cómo se ejecutó la intrusión. El resultado final: root shell del sistema objetivo obtenido por la propia IA.

Técnicas y herramientas mencionadas

  • HexStrike AI: framework ofensivo open source basado en MCP, puente entre IA y herramientas de seguridad.
  • MCP (Model Context Protocol): capa de conexión entre el agente y el sistema.
  • Claude Desktop: cliente del modelo, configurado vía archivo de settings con la ruta de HexStrike.
  • Kali Linux: sistema anfitrión del despliegue.
  • Entorno virtual de Python: aislamiento de la instalación y sus dependencias.
  • +150 herramientas gestionadas: reconocimiento de red, apps web, autenticación, análisis binario, contenedores, CTF/forense, bug bounty, OSINT.
  • +12 agentes de IA especializados: optimización y automatización de tareas ofensivas.
  • Laboratorios PortSwigger: banco de pruebas de aplicaciones web.
  • Escaneo de puertos y vulnerabilidades: backdoor FTP y hallazgos high/critical reportados.
  • Botón de explotación directa: obtención de root shell desde la interfaz del agente.

Conclusiones

  • El patrón MCP convierte un asistente conversacional en un operador con manos: sin integración con herramientas reales, la IA solo describe; con ella, ejecuta.
  • El flujo prompt → permisos → explotación reduce un lab de 10-15 minutos a pocos minutos, y escala el mismo patrón a escaneos completos con explotación de un clic.
  • La potencia no exime del marco ético: la herramienta es para fines educativos y pruebas autorizadas, no para uso malicioso.
