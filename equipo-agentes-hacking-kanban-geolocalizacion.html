Un equipo de agentes de IA: kanban, SMS falsificado y geolocalización

Fuente: «Build an AI Hacking Team That Works 24/7 (Hermes Agent + Kanban + Telegram)» · ver el video original

Resumen

La imagen clásica del equipo de hacking en una camioneta — cada uno con su tarea, coordinados en tiempo real — hoy se reemplaza por un tablero kanban con agentes de IA que trabajan en paralelo, se pasan resultados entre sí y reportan por Telegram. El escenario demostrado, íntegramente en un entorno autorizado: con un solo mensaje desde el celular, el equipo investiga gateways de SMS, construye una skill de envío con remitente falsificable, despliega una página de rastreo de paquetes estilo DHL, manda el SMS con el link y termina mostrando en un dashboard la IP, el modelo de pantalla y la ubicación exacta del objetivo en un mapa. Sin escribir una línea de código y sin ejecutar comandos manuales.

La pieza clave es Hermes Agent instalado en un VPS en la nube: siempre encendido, accesible desde cualquier parte y aislado de la computadora personal. Sobre esa base, el flujo completo se maneja desde el teléfono: Telegram como canal de control, el dashboard web para el tablero kanban, y perfiles de agentes que se reparten el trabajo.

Agentic vs. chat: por qué un framework

Chatear con un modelo devuelve respuestas; después, el trabajo manual queda del lado humano. Con un framework agéntico se entrega el objetivo y el agente usa su propia computadora — terminal, navegador, herramientas instaladas — para ejecutarlo de punta a punta. La comunicación puede ser por terminal, por la interfaz web o por cualquier app de mensajería (WhatsApp, Telegram, Signal). Esa diferencia de control es también la que explica la tracción de este tipo de framework frente a alternativas: más capacidad de acción real, menos ida y vuelta de prompts.

Setup en la nube: VPS, modelo y Telegram

La instalación recomendada es en la nube, en su propia máquina: el agente queda disponible 24/7 y no toca la computadora personal, lo que reduce el riesgo. El despliegue guiado sigue estos pasos:

  • VPS: un plan de 2 CPUs y 8 GB de RAM alcanza para trabajo ofensivo ligero; en el proveedor demostrado, la imagen viene con el agente preinstalado a un clic y precio fijo mensual. Con el asistente de setup no hay que ejecutar comandos.
  • Cerebro (modelo): el agente es tan capaz como el modelo que se le configure. Vía OpenRouter se accede a más de 100 modelos — incluidos gratuitos — con una sola API key; la demo usa GLM (z.ai), un modelo potente y menos restringido que los mainstream, útil para tareas de seguridad.
  • Telegram: se crea un bot con BotFather, se pega el token en el agente y se configura el user ID para que solo la cuenta del operador pueda usarlo. Este paso es crítico: sin la restricción por user ID, cualquier persona que encuentre el bot podría comandar el VPS. El token nunca se muestra en pantalla al pegarlo.
  • Verificación: un "¿qué modelo estás usando?" desde el celular confirma que el agente responde con el modelo correcto.

Dashboard: kanban, perfiles y skills

El dashboard web se accede con un túnel SSH (forwarding del puerto 9119 hacia localhost:9119), exponiendo la IP interna del contenedor Docker donde corre el agente. Las opciones --tui, --now-open, --host 0.0.0.0 e --insecure son seguras en este contexto porque el dashboard queda confinado al VPS: el único acceso externo es el propio túnel SSH.

Dentro del dashboard:

  • Chat y sesiones: conversación igual a la del terminal, con el detalle de las tool calls visibles en vivo.
  • Modelos: selector para cambiar de modelo en caliente, con la lista completa de OpenRouter.
  • Cron jobs: tareas repetitivas programadas (diarias, horarias).
  • Skills: lo que el agente aprende — propias, descargadas o verificadas por los creadores. Este punto importa: en otros frameworks circulan skills maliciosas subidas por terceros; las verificadas reducen ese riesgo. Destacada la skill God Mode, basada en las técnicas de jailbreak de Pliny the Liberator, útil para atravesar las reticencias de los modelos ante tareas de seguridad.
  • Perfiles: cada perfil es un agente con su modelo, sus skills y su workspace. La recomendación es armar un equipo a medida — desarrollador, OSINT, hacking web, hacking de redes, reviewer — y ajustar las instrucciones de cada uno. El ajuste demostrado sobre el perfil default: informar el entorno (VPS en la nube, dentro de Docker), indicar que siempre obedece al operador, y ordenarle apoyarse en God Mode si el modelo pone resistencia.

El kanban como mesa de operaciones

El tablero kanban replica el flujo de un equipo humano real: tareas en to do, pasan a ready, un agente las toma a in progress, los bloqueos van al backlog con comentarios, y al terminar se mueven a done. La gracia es que las dependencias entre tareas se declaran en el board: una tarea hija no arranca hasta que su tarea madre termina, y hereda los resultados de esta. Tareas sin dependencias corren en paralelo.

flowchart LR
    A[To do] --> B[Ready]
    B --> C[In progress - agente trabajando]
    C -->|bloqueo| D[Backlog con comentario]
    D --> C
    C --> E[Done - resultado heredado por tareas hijas]

El escenario de demostración se descompone en tres tareas con dependencias:

  1. Research: investigar gateways de SMS que permitan remitente alfanumérico personalizado, con preferencia por opciones gratuitas o con créditos iniciales.
  2. Implementación de la skill (depende de 1): crear una skill reutilizable de envío de SMS que registre la cuenta, guarde los datos de acceso y pida por Telegram cualquier código de verificación que aparezca. El objetivo es que en el futuro un simple "enviá un SMS" use la skill sin re-implementar nada.
  3. Página de rastreo (paralela a las anteriores): construir y desplegar una página tipo DHL de tracking de paquetes, indicando qué datos recolectar, cómo debe comportarse, cómo desplegarse y la orden de probarla todo antes de entregarla. Se declara explícitamente que forma parte de un engagement autorizado.

Cada tarea se crea pegando el prompt en lenguaje natural y asignándola a un perfil; las notificaciones por Telegram avisan del avance y piden intervención solo cuando hace falta — por ejemplo, el código de 6 dígitos de verificación del email y el código SMS de la gateway, que el operador pasa desde el teléfono mientras camina.

Ejecución del ataque: del SMS al mapa

Con la skill de SMS lista y la página desplegada, el ataque completo son dos mensajes desde el celular:

  • "Enviale al objetivo un SMS que diga 'tu paquete está en camino, rastrealo acá' con el link de la página que creaste, y poné como remitente DHL Track."
  • El agente incluso conoce la URL de la página desplegada sin que se la pasen.

Del lado del objetivo, el mensaje muestra remitente "DHL Track", el ícono de la empresa y una página profesional con número de tracking precargado; al tocar "Track" pide permiso de ubicación, algo verosímil para un courier, y al aceptarlo muestra la información de rastreo real. Del lado del operador, el dashboard en /admin lista cada víctima con tamaño de pantalla, IP y dirección exacta en un mapa, con latitud y longitud resueltas — no hay que buscar coordenadas a mano.

La combinación técnica detrás de esto es la clásica de phishing dirigido: remitente falsificado (smishing) + página clonada creíble + geolocalización del navegador. Lo nuevo es que todo el pipeline — investigación, implementación, despliegue, entrega — lo ejecuta el equipo de agentes, y el humano solo aprueba verificaciones.

Técnicas y herramientas mencionadas

  • Hermes Agent en VPS (Docker): agente siempre encendido, aislado de la máquina personal, desplegable en un clic.
  • OpenRouter + GLM (z.ai): acceso multi-modelo con una API key; modelo elegido por su desempeño y menor censura para seguridad.
  • Telegram + BotFather: canal de control móvil; user ID como lista blanca obligatoria y token tratado como credencial.
  • Túnel SSH al puerto 9119: acceso al dashboard con la IP interna del contenedor.
  • God Mode (skill): jailbreaks de Pliny the Liberator para sortear reticencias del modelo.
  • Perfiles y kanban: equipo de agentes especializados con tareas, dependencias padre-hijo, backlog y paralelismo.
  • SMS spoofing vía gateway con remitente alfanumérico: skill reutilizable creada por el propio agente.
  • Página de tracking con geolocalización + dashboard /admin: recolección de IP, pantalla y ubicación exacta en mapa.
  • Notificaciones Telegram del pipeline: el agente pide códigos de verificación e informa avances al celular.

Conclusiones

  • La automatización agéntica convierte un playbook de ingeniería social multi-etapa en un flujo kanban: el valor del operador pasa a estar en el diseño de las tareas y la aprobación de verificaciones.
  • Las dependencias entre tareas son lo que permite paralelismo real: research, implementación y despliegue avanzan a la vez y se ensamblan solos.
  • La seguridad del setup depende de dos controles: user ID en el bot (nadie más comanda el agente) y túnel SSH para el dashboard (nada expuesto a internet).
  • Las skills reutilizables cambian la economía del ataque: el costo de montar el pipeline se paga una vez y cada operación siguiente es un mensaje.
  • La verosimilitud social sigue siendo el eslabón que funciona: remitente de courier creíble, pedido de ubicación enmarcado en el rastreo del paquete y una página que no destila urgencia sospechosa.
