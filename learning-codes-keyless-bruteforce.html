Códigos de aprendizaje: abrir autos con fuerza bruta de radiofrecuencia

Fuente: «DEF CON 32 - How I hacked Learning Codes of the key job of a car assembled in my country - D. Erazo» · ver el video original

Resumen

Una parte considerable de los sistemas keyless entry instalados —sobre todo en Suramérica, donde los concesionarios montan equipos universales— no usa rolling code sino learning code: chips como el HS2240 que aprenden el código del control al programarse y lo repiten de forma esencialmente fija. Esta investigación demuestra que esos sistemas son abribles por fuerza bruta de radiofrecuencia en minutos, sin tocar el auto y sin posesión previa del control.

El trabajo parte de un hallazgo casual al buscar inyección CAN por el puerto OBDII: el CAN ID 545, asociado a bloquear y desbloquear con el mando, desvió la atención hacia la capa de radiofrecuencia. Con capturas en 370 MHz, modulación ASK, ingeniería inversa del chip de learning code con un analizador lógico y un transmisor SDR, se reconstruyó por completo el formato de la señal y se construyó una herramienta —Outdoor RF Killer, unas 1.030 líneas de Python— capaz de forzar códigos, programar puertas traseras en el receptor y lanzar ataques roll jam contra sistemas de rolling code.

La señal: 96 bits que no cambian

La captura con Universal Radio Hacker reveló lo esencial: la señal de desbloqueo es de 370 MHz en ASK con 500 símbolos por segundo, y al comparar varias pulsaciones, la primera y la segunda fila de bits eran idénticas. Un ataque de replay lo confirmó: desde un quinto piso de un edificio abandonado, con el auto en el primero, la misma señal volvió a abrir el vehículo. No hay rolling code; hay un código fijo disfrazado.

El formato del frame quedó claro al analizarlo: un preamble, 20 bits de código y 4 bits de modo —uno por cada botón del mando, incluidos bloquear y desbloquear—. Con 20 bits, el espacio es de apenas 2^20, cerca de un millón de códigos posibles. En hexadecimal, la señal de bloqueo era casi idéntica a la de apertura: solo cambiaban los tres últimos dígitos.

Ingeniería inversa del chip con analizador lógico

El desarme del mando identificó el chip de learning code HS2240, con oscilador a 370 MHz, dos baterías de 6,38 V totales, cuatro entradas —una por botón— que pasan por resistencias pull-down, y la señal codificada saliendo por el pin 3 hacia el modulador ASK.

La incógnita era la codificación: las capturas mostraban pulsos de distinta duración, no unos y ceros limpios. Con un analizador lógico LA5016 a 500 MHz —canal 1 al pin de transmisión, canal 2 a las entradas de botones— se descifró el esquema: cada bit se envía como 4 símbolos. Un 0 se transmite como 1000 y un 1 como 1110. El preamble es una constante de 1 seguido de 31 ceros. La cuenta cierra: 20 bits de código × 4 símbolos + 4 bits de modo × 4 símbolos = 96 bits, exactamente lo capturado. Además, el chip repite la trama 25 veces seguidas mientras el botón está presionado.

Ese conocimiento no solo permite decodificar cualquier señal, sino generarlas desde cero. También corrigió información engañosa de los datasheets, que prometen cosas como "reduce any code collision and authorized code scanning possibilities" para toda la familia de chips vulnerables: HS1527, HS2240, HS2241, HT12D y variantes.

Fuerza bruta en el mundo real

El bloque de ataque se construyó con GNU Radio sobre HackRF, con repetición e interpolación para mejorar la señal, portadora multiplicada y modulación ASK. El ataque fuerza el espacio de un millón de códigos; el retardo entre señales es configurable —con interferencia, conviene espaciar más—. En las demostraciones, autos concretos se abrieron en cerca de un minuto de script, con dos códigos de aprendizaje distintos en el mismo vehículo: el receptor guarda hasta 4 códigos, y el ataque los cubrió uno tras otro.

Se probaron vehículos de varias marcas ensamblados en Ecuador, incluyendo modelos como el Kia Picanto y, al parecer, un Renault con keyless universal instalado por el concesionario. El mismo esquema aplica a garajes y otros dispositivos de RF que usan learning code.

Puertas traseras programadas desde la radio

El detalle del receptor que guarda hasta 4 códigos de aprendizaje abre otra vía: el modo de programación se activa conectando la ignición a la alimentación y pulsando un botón seis veces. Con el receptor en modo programación, cualquier señal enviada por RF queda guardada como código válido.

Un atacante puede entonces programar un código arbitrario elegido por él —por ejemplo 1001001 o 00000001— como llave del vehículo. Después de salir del modo de programación, ese código abre el auto para siempre, desde un HackRF o cualquier transmisor. En el contexto de Suramérica, donde circulan controles universales que se instalan en muchos autos, la idea de un keyless con puerta trasera instalada de fábrica o por terceros deja de ser paranoia: no hay forma de que el propietario sepa qué códigos guarda su receptor.

Colisiones: un millón de llaves para todo el planeta

Todos los chips de learning code de esta familia comparten el mismo espacio de 2^20 —un millón de códigos—. Dado el volumen de autos y controles que usan estos chips en el mundo, es estadísticamente inevitable que mandos distintos compartan el mismo código, y que una señal aleatoria abra autos ajenos: el mando de una persona podría desbloquear la puerta de un garaje en Estados Unidos o el auto del vecino. Es posible que ese umbral de colisión ya se haya alcanzado, y nadie lo habría notado todavía.

Técnicas y herramientas mencionadas

  • Learning code (HS2240, HS1527, HS2241, HT12D): chips cuyo código se programa en el receptor y se repite fijo, a diferencia del rolling code.
  • Universal Radio Hacker: captura, demodulación y análisis de la señal en 370 MHz / ASK / 500 símbolos por segundo.
  • Analizador lógico LA5016: reconstrucción de la codificación por símbolos (0 = 1000, 1 = 1110) y del preamble.
  • HackRF + GNU Radio: generación y transmisión de las señales de fuerza bruta, jamming y backdoor.
  • Replay attack: verificación inicial de que el código es fijo, desde otro edificio.
  • Modo de programación del receptor: ignición a alimentación + 6 pulsaciones; permite almacenar códigos arbitrarios por RF.
  • Roll jam: ataque contra rolling code que la herramienta implementa con dos dispositivos SDR.
  • Outdoor RF Killer: herramienta final en Python (~1.030 líneas): fuerza bruta con base de datos de codificaciones de chips, parámetros arbitrarios de ataque, creación de backdoors, replay, jamming configurable y grabación/replay para auditar si un auto es vulnerable.

Conclusiones

  • Los sistemas keyless con learning code son abribles por fuerza bruta en minutos: el espacio de 20 bits es trivialmente pequeño para un SDR moderno y la señal no rota.
  • La codificación por símbolos no es una protección: una tarde con analizador lógico la reduce a un formato trivialmente generable.
  • Un keyless puede quedar con puerta trasera programada remotamente durante su modo de emparejamiento, sin señal alguna para el propietario; la única defensa práctica es auditar qué códigos tiene almacenados el receptor.
  • La collision problem de un millón de códigos compartidos globalmente convierte estos chips en un problema colectivo, no individual: llaves ajenas pueden abrir otros autos y garajes.
  • La herramienta pública permite además a propietarios y auditores descubrir si su propio vehículo usa código fijo o vulnerable.
