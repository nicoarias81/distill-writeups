GodMode Mobile: explotar apps críticas con técnicas de cheats de juegos

Fuente: «God Mode Mobile: Exploiting Mobile Apps With Game Cheats - Bruno Sena» · ver el video original

Esta es la historia de cómo un hobby —el game hacking, que además fue la puerta de entrada a la seguridad ofensiva— terminó en un bypass completo de la autenticación de un gestor de contraseñas con más de un millón de descargas en Play Store. La pregunta que disparó la investigación: las técnicas que uso para hacer trampa en juegos de Android, ¿sirven para explotar aplicaciones críticas como un banco o un password manager?

Calentamiento: god mode en AssaultCube

El primer objetivo fue AssaultCube, un juego desarrollado originalmente para PC con un motor C++ simple, que después recibió un port a Android. Como toda la lógica del juego vive en la librería nativa (libmain.so, dentro de /lib/arm64-v8a), el análisis va directo a Ghidra. El motor es tan simple que conserva los símbolos de depuración, así que encontrar la función doDamage —que recibe el entero de daño, las dos entidades (quién pega y quién recibe) y el ID del arma— es inmediato. Y junto a ella, el dereference a la instancia del jugador propio.

El cheat de god mode con Frida es casi trivial: cada vez que doDamage se llama sobre mi personaje, se parchea el daño a cero; cuando la víctima es otro jugador, el valor queda intacto. Resultado: invencibilidad conservando la capacidad de matar. Nada notable todavía —pero sirve para fijar el patrón: encontrar la función, entender los argumentos, hookear con Frida.

El giro: encontrar Mono donde no lo esperabas

Buscando apps Android con la misma estructura —lógica nativa portada desde Windows— aparece KeePass2Android: un port no oficial del famoso gestor de contraseñas, pero con más de un millón de descargas. Al analizar el Java con JADX en busca de loadLibrary, las librerías cargadas delatan algo familiar: monogen, mononative, monodroid. Mono: la VM que ejecuta los juegos de Unity.

El desvío por Cuphead —juego de 2017 desarrollado con Unity sobre Mono Runtime— sirve para entender el terreno:

  • Mono Runtime usa compilación JIT: genera bytecode CIL (Common Intermediate Language) que se ejecuta en la VM, tal como el JVM de Android. Rendimiento moderado, y el bytecode queda accesible para análisis.
  • IL2CPP compila ahead-of-time: convierte el bytecode a C++ y elimina el código original, lo que dificulta enormemente el reverse engineering (es posible, pero mucho más trabajoso).

En Cuphead, la carpeta Managed contiene los DLLs con la lógica del juego, y el central es Assembly-CSharp.dll. Con dnSpy se descompila, se busca la propiedad de daño básico del disparo (valor 4), se cambia a un número ridículo y se recompila: un disparo mata a cualquier jefe. Otra vez el mismo patrón: localizar la lógica, alterarla, recompilar.

Xamarin y las librerías escondidas

De vuelta en KeePass2Android, el problema es que ningún DLL visible contiene la lógica del gestor: solo librerías de Mono y de Xamarin, el framework de desarrollo multiplataforma de Microsoft (un solo código en C#/.NET compilado para Android, iOS y Windows). La pieza encaja: Xamarin corre sobre Mono Runtime.

Dentro del APK, una carpeta mono con clases como MonoPackageManager lleva a los archivos assemblies.blob y assemblies.manifest: todas las librerías de la app empaquetadas en un solo blob, con el manifest como mapa para reconstruirlas. La herramienta PyXamStore —publicada junto a un artículo de GoSecure sobre bypass de certificate pinning en apps Xamarin— deshace el empaquetado y extrae todos los DLLs, incluidos los de KeePass2Android.

El mismo artículo aporta otra pieza clave: un módulo de Frida para manipular Mono Runtime, demostrado con un bypass de certificate pinning que hookea HttpClientHandler y reemplaza el handler por uno que no valida certificados (sin el script: SSL exception; con el script: OK).

El exploit: QuickUnlock sin contraseña

Con los DLLs en dnSpy, el análisis retrocede un paso al Java para entender la app: en el Android Manifest aparecen dos activities relevantes. PasswordActivity, donde el usuario ingresa la contraseña maestra que desbloquea la base de datos, y QuickUnlock, una función de KeePass2Android que desbloquea la base ingresando solo los últimos tres caracteres de la contraseña maestra.

La lógica de QuickUnlock vive en el DLL KeePass2AndroidLib. En dnSpy, el método OnUnlock es decepcionantemente simple: compara el string del EditText contra expectedPasswordPart y, si coincide, llama a UnlockAndSyncClose, que abre la base con todas las contraseñas.

flowchart LR
    A[APK de KeePass2Android] --> B[PyXamStore: extraer DLLs del assemblies.blob]
    B --> C[dnSpy: mtodo OnUnlock en KeePass2AndroidLib]
    C --> D[Frida + mdulo Mono Runtime]
    D --> E[OnUnlock dispara UnlockAndSyncClose directamente]
    E --> F[Base de contraseas desbloqueada sin validar nada]

El exploit con Frida encadena todo: enumera los DLLs del proceso hasta encontrar el objetivo, hookea la clase QuickUnlock, instancia los métodos OnUnlock y UnlockAndSyncClose, y reemplaza la comparación por una llamada directa: cada vez que OnUnlock se invoca, se llama UnlockAndSyncClose inmediatamente, sin validar nada.

La demostración es contundente: con contraseña incorrecta, la base no abre; con el script activo, cualquier texto —o directamente nada— desbloquea el gestor completo. El bypass total de la autenticación cabe en un script de Frida.

Lecciones del Q&A

  • ¿Sirve ofuscar? Mono Runtime no ofusca: el bytecode queda almacenado en los archivos de la aplicación. IL2CPP, en cambio, compila a nativo y aporta una capa de protección real. Pero Xamarin necesita Mono para ejecutar un único código C# en múltiples plataformas: es una decisión de conveniencia que hace el código más inseguro.
  • ¿Y si el código estuviera ofuscado? El análisis mostrado fue estático, con el objetivo ya identificado. Con ofuscación haría falta análisis dinámico previo; en Android, Frida y Objection (que se apoya en Frida) son las herramientas de referencia para debuggear sin el código fuente y entender funciones como QuickUnlock en runtime.

Cierre

El recorrido completa un arco que va del cheat más básico al bypass de autenticación de un password manager usando siempre el mismo método: encontrar dónde vive la lógica (Ghidra para nativo, dnSpy para .NET), entender cómo funciona y manipularla en runtime con Frida. La moraleja es doble: las técnicas de game hacking son herramientas ofensivas de pleno derecho contra apps móviles, y las apps construidas sobre Mono/Xamarin exponen su lógica completa a quien sepa desempaquetar un assemblies.blob.
