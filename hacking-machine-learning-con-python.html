Hacking de machine learning con Python: de la teoría al código

Fuente: «Python para hacking de machine learning"- Christian Camilo Urcuqui López - AI RESILIENCE HUB» · ver el video original

Resumen

La inteligencia artificial dejó de ser un tema de laboratorio para convertirse en software en producción, y todo software tiene errores. La premisa que atraviesa este recorrido es simple y demoledora: un modelo de machine learning es vulnerable por construcción, porque se apoya en estadística y porque detrás de cada predicción hay un error que puede atacarse. En lugar de quedarse en la teoría, aquí se recorren vulnerabilidades reales del pipeline de machine learning y se muestran, con código Python abierto, cómo explotarlas: desde modelos envenenados descargados de Hugging Face hasta ataques adversarios sobre redes de visión y un agente ofensivo llamado Orión.

El marco conceptual es la evolución de la ciberseguridad hacia tres capas: el hacking tradicional, el adversario de machine learning (quien sabe atacar los modelos) y el hacking de agentes (quien explota sistemas autónomos con prompt injection). Esta nueva superficie exige también pensar el componente ético: desarrollar agentes sin comité de ética ni guardrails equivale a fabricar armas sin control.

Por qué los modelos se rompen

Los sistemas de ciberdefensa tradicionales responden al pasado: primero ocurrió el ataque, después se creó la vacuna. El machine learning promete un paso más —predecir a partir de patrones— pero toda predicción conlleva error, y ese error es la puerta de entrada. A esto se suma la complejidad del ciclo de vida de un modelo: recolección de datos, almacenamiento, procesamiento, modelado, despliegue y monitoreo. Cada fase tiene ataques documentados, desde datos manipulados o sintéticos que sesgan el modelo hasta el envenenamiento directo, la inyección en el pipeline de despliegue y la manipulación del reentrenamiento.

Un ejemplo clásico: Hugging Face funciona como el GitHub de los datos científicos, un repositorio donde cualquiera descarga modelos preentrenados. Durante un tiempo, cualquiera podía publicar modelos ahí, y un científico de datos sin formación en seguridad podía descargar un modelo con inyección incluida. La vulnerabilidad no estaba en la plataforma sino en el eslabón humano: quien usa un modelo sin preguntarse de dónde viene.

Ataque 1: manipular a los vecinos para aprobar un crédito

El primer ataque es un feature attack sobre un modelo clásico de vecinos cercanos. La escena: un sistema que clasifica solicitantes de crédito en aprobados y rechazados. El objetivo del atacante no es tocar al registro propio —eso levantaría sospechas— sino manipular sutilmente los atributos de sus vecinos más cercanos en el espacio de features, de modo que el modelo reclasifique al objetivo como aprobado sin que el registro del objetivo muestre ninguna modificación. El código es Python básico y está publicado; la lección es que los ataques adversarios no requieren redes neuronales: cualquier modelo que tome decisiones por similitud es manipulable.

Ataque 2: deepfakes que engañan al detector

El segundo escenario ataca la visión por computadora. El proyecto de referencia, In Your Face AI, es un detector biométrico entrenado para distinguir caras reales de deepfakes. En vivo, el modelo detecta correctamente una imagen manipulada como falsa. Después viene el ataque:

  • Una imagen no es más que una matriz numérica RGB.
  • Se multiplica esa matriz por una máscara de perturbación diseñada para empujar la representación interna del modelo hacia la clase "real".
  • El resultado es una nueva imagen del mismo sujeto que el detector clasifica como 100% real.

Lo inquietante es el doble resultado del ataque: el modelo queda engañado y, al mismo tiempo, el ojo humano no percibe diferencia entre la imagen original y la alterada. La manipulación existe solo en el espacio matemático del modelo.

Ataque 3: cajas blancas, grises y negras con frameworks listos

La analogía con el hacking tradicional es directa: según el conocimiento que tenga el atacante sobre el modelo, el ataque será de caja blanca (pesos y arquitectura conocidos), gris o negra. Para cada escenario existen técnicas con nombre propio —Carlini, SimBA, HopSkipJump— y, más importante, frameworks que las implementan. El más destacado es ART (Adversarial Robustness Toolbox): una librería de Python donde las matemáticas del ataque ya están empaquetadas. Con pocas líneas —importar el método, definir si hay GPU disponible, cargar los pesos del modelo víctima, ejecutar el ataque— una imagen clasificada como falsa pasa a clasificarse como real. Hay equivalentes para texto, como TextAttack, para atacar clasificadores de spam o modelos de lenguaje.

Orión: el agente que orquesta ataques

El proyecto final de la serie se llama Orión, un agente pensado con la lógica de El arte de la guerra: primero "conoce a tu enemigo", después ataca. Orión recibe una descripción del ataque sufrido, identifica las técnicas y propone soluciones —una interfaz amable para quien no tiene formación en el tema—. Pero da un paso más: si detecta algo vulnerable, también propone atacar. Su interfaz permite cargar los pesos de un modelo, definir la cantidad de salidas, elegir la imagen objetivo y generar el dato adversario de forma automática, que luego el propio detector clasifica como real. La hoja de ruta es ambiciosa: automatizar la extracción de modelos matemáticos de papers científicos para que Orión orqueste ataques sobre texto, audio y otros formatos.

Un proyecto aparte merece mención por su diseño: una inteligencia artificial adversaria para generar conciencia sobre phishing, construida con reinforcement learning. La IA genera el ataque, el usuario decide si cayó, y ese feedback reentrena al modelo —basado en White Rabbit— para producir phishing cada vez más adaptado a la organización. El phishing deja de ser estático y se vuelve un oponente que aprende de cada interacción.

Lecciones que quedan

  • Todo modelo es hackeable. No es una exageración retórica: la naturaleza estadística del machine learning garantiza errores explotables, en modelos tradicionales y generativos.
  • La ofensiva está al alcance de todos. Frameworks como ART y TextAttack reducen un ataque adversario a unas líneas de Python. Asumir que hace falta ser investigador para lanzarlos es subestimar el riesgo.
  • El pipeline completo es superficie de ataque. Datos, repositorios de modelos, entrenamiento, despliegue y reentrenamiento: cada fase tiene técnicas documentadas y casos reales.
  • El lenguaje es la frontera. Los modelos fallan con variaciones regionales y ambigüedades porque, al final, el texto son números. Ahí es donde viven muchos de los hacks.
  • Falta gobernanza. Muy pocas organizaciones tienen comités de ética de inteligencia artificial, y desarrollan agentes sin evaluar justicia, diversidad, explicabilidad ni seguridad. Con la llegada de los agentes autónomos, ese vacío deja de ser teórico.
