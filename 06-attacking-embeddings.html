AI-300 Module 6 — Attacking Embeddings

Fuente: material del curso correspondiente (sin video público)

Distilled from OffSec AI-300 (OSAI) course material (module 6) — internal training reference, not for redistribution.

Objective

Recover plaintext — passwords, API keys, connection strings — from vectors stored in a vector database. The operative misconception is that embeddings behave like hashes ("one-way, so even if attackers capture them, they can't do anything"); embeddings exist to preserve semantic meaning, and preserved meaning means recoverable information. Three attack categories: embedding inversion (reconstruct text from a vector), membership inference (is value X in this embedding? — AML.T0024.000), and attribute inference (classify a vector's topic/sentiment for triage). Overall mapping: AML.T0024 (Exfiltration via ML Inference API).

Four approaches, ordered by prep time and by the typical time-constrained decision path:

Category Model access Real pairs needed Training Tools (module)
Zero-shot inversion Known, local or API None None ZSInvert, Zero2Text
Few-shot inversion Can be unknown Small number of leaked/injected pairs; alignment plateaus at ~1,000–3,000 Moderate (decoder) + light (alignment) ALGEN
Supervised inversion Known, local Self-generated (thousands+) Heavy Vec2Text
Surrogate (transfer) Unknown None from target Moderate (on surrogate) — (GEIA/TEIA exist in research)

Hard limitations that shape tool choice: token length (Vec2Text best on 32 tokens, ZSInvert tested to 64; production chunks are 256–512 tokens, so results on real chunks degrade vs. papers — short chunks like credential snippets are the softest targets); high-entropy tokens (random passwords/API keys/hashes carry no semantic signal — LLMs can't guess them, decoders never saw them); model identification (zero-shot and supervised need the model; only surrogate and few-shot work without it); dimensionality reduction / quantization (PCA, product/scalar quantization destroy inversion-relevant precision); domain mismatch (decoders trained on MSMARCO/NQ drop on off-domain text).

Target surface

Continuing the Megacorp One AI assessment: a Weaviate vector DB (port 8080, unauthenticated) and RAG chat UI (port 80) on one host; SSH as attacker / attacker_attacker. Collection: DocChunk. The maturity gap is the point — vector DBs bolted auth/RBAC/encryption on after release, and the "embeddings are one-way" belief makes operators relax what little control exists. Attack surface = the vector store itself (export), the RAG chat endpoint (inference probing), and write access to the store (ALGEN canaries).

Techniques

2. Identify the embedding model

  • Check the vector DB's own config first (many DBs embed at ingestion; the model name sits in schema config or env vars).
  • Dimensionality fingerprint:
query = """{ Get { DocChunk(limit: 1) { _additional { vector } } } }"""
r = requests.post("http://localhost:8080/v1/graphql", json={"query": query})
vec = r.json()["data"]["Get"]["DocChunk"][0]["_additional"]["vector"]
print("Vector length:", len(vec))    # -> 384

Reference dimensions: OpenAI ada-002 = 1536, text-embedding-3-small = 1536, text-embedding-3-large = 3072, Cohere embed-english-v3.0 = 1024, all-MiniLM-L6-v2 = 384, BGE-base = 768. Non-unique — a first filter only.

  • Inference probing (works with just exported vectors + a chat endpoint, even through strong guardrails): query the RAG chat with verbatim/factual/broad prompts, split responses into sentences, sentence pairs (chunk content often spans two sentences), and full text; embed each segment with every dimension-matched candidate model; rank by cosine similarity against the exported vectors. Correct model ≥ 0.85 (paraphrase-tolerant), wrong models ~0.5–0.6 despite same dimensionality — different geometry.

The script can also save matched text-embedding pairs for ALGEN alignment. Bonus: if a second RAG system in the environment shares the embedding model, probing can run against that one instead.

3. Triage chunks (attribute-inference-driven targeting)

Full inversion costs minutes per chunk; most of a production store is mundane. chunk_triage_pipe.py chains three stages, all in embedding space:

  1. Density — score every chunk on isolation (credential chunks sit alone; policy pages cluster) and relevance to sensitivity probes (short texts resembling credentials/API keys/SSH keys/PII). Top 50 pass.
  2. Contrastive pairwise (PW) — positive vs. negative probe banks, RRF across multiple weightings, cluster normalization to surface secrets buried among structurally similar mundane content. Top 20 pass.
  3. Reconstruction — shallow inversion per candidate using enterprise document templates (customizable with --company), then credential scoring: regex patterns, Shannon entropy, character-class diversity.

Fusion: weighted RRF (density 1.0, PW 1.5, recon 2.0). Output on the lab store: top-3 fused scores cluster above 0.071, fourth drops to 0.068 — the gap is the natural cutoff; invert only those. Extract a target:

$ python3 -c "import numpy as np; np.save('chunk_23.npy', np.load('export/embeddings.npy')[23:24])"

Chunk numbering varies with ingestion order; scores don't. Flags: --top N, --company NAME.

4. Zero-shot #1 — template bank + membership inference (emb_fin.py)

Inversion can't reproduce high-entropy tokens (the space encodes "this is a password field", not which password). Split the problem: recover structure with templates that use placeholders, then fill placeholders by membership inference — embed template-with-candidate against the target vector; the true value wins on cosine similarity because it reproduces the exact original token sequence.

Build the bank — generate_templates.py auto-detects the domain from signature-phrase similarity (lab: it_password 0.4618 vs. cloud_azure 0.3002), then expands 7 base templates via four strategies (pattern-based, linguistic variations, structural variations, contextual wrapping) into hundreds of thousands of unique templates:

$ python3 generate_templates.py --output templates.json embeddings.npy --count 500000
[+] Detected domain: it_password ...
Final count: 582,727

Wordlist for the slot filler:

$ wget -O passwords.txt https://raw.githubusercontent.com/danielmiessler/SecLists/refs/heads/master/Passwords/Common-Credentials/100k-most-used-passwords-NCSC.txt

Run:

$ python emb_fin.py embeddings.npy --chunk 0 --templates templates.json \
    --wordlist passwords.txt --slots PASSWORD \
    --default-URL https://login.megacorpone.ai --max-templates 500000
...
[Progressive] Locked slots: PASSWORD=N0=Acc3ss
 Extracted values:
 + PASSWORD = N0=Acc3ss
   Likely — 18/20 templates agree, narrow statistical margin

Why naive top-20 scoring fails and what the script does instead: adaptive template selection (relative similarity threshold, not fixed N), diversity clustering (greedy near-duplicate removal so the vote is independent), two-stage narrowing (full wordlist against a few seed templates, then a tournament of survivors across all diverse templates), margin-aware scoring (candidate's lift over a neutral baseline — prevents "mega123" winning on a Megacorp corpus because of semantic overlap). Plus weighted consensus, gap-based confidence, and progressive fill-and-lock for multiple slots. Verify against the source doc (pdftotext MC1_password_reset.pdf → The default password after resetting is N0=Acc3ss ...).

Failure modes worth knowing: attractor candidates (same winner across unrelated chunks = noise); oversized wordlists swamp the password's 5–10% embedding-variance contribution — cut to 500–5,000 targeted entries and shorten surrounding context. Recoverability boundary: values with semantic signal (meaningful passwords like AutoEnroll99!, usernames, hostnames, URLs) are recoverable; truly random strings (1qaz2wsx3edc4rfv) tokenize into meaningless subwords, land in the ~0.0001 cosine noise floor, and are not recoverable this way — that's a training-objective property, not vector capacity (1536/3072-dim models retain a bit more lexical detail but still don't prioritize it).

5. Zero-shot #2 — beam-search inversion (zero2text_impl.py)

Fallback when no template in the bank matches the target's structure. Based on Zero2Text (arXiv 2602.01757v2): GPT-2 proposes next tokens, each candidate extension is embedded and scored by cosine similarity to the target, best beams kept, converging over ~30–40 steps. The course implementation adds: automatic high-entropy region detection (per-character Shannon entropy + multi-character-class, plus regex for sk- keys, eyJ JWTs, hex hashes, mixed-class passwords), slot typing from surrounding keyword context ({PASSWORD}, {API_KEY}), then merges the generated template with the bank's top-50 (diversity-clustered) and runs the same slot filler.

$ python3 zero2text_impl.py embeddings.npy --chunk 0 --templates templates.json \
    --wordlist passwords.txt --slots PASSWORD \
    --default-URL https://login.megacorpone.ai --max-templates 500000
[Zero2Text done] 8 steps, similarity=0.9160        # early stop: stagnation
Inversion: 91.6% similarity
Found 1 high-entropy region(s)
...
+++ PASSWORD = N0=Acc3ss
    Strong — 4/5 templates agree, 3.1x ahead of runner-up

Dual-embedder mode (--local-model): a separate local embedder scores beam candidates and a ridge-regression matrix maps into the victim's space — cuts victim-model queries from thousands to dozens per step (useful against paid APIs or for stealth), at the cost of projection approximation error. Direct mode is more reliable when you have the model locally.

Decision rule: run emb_fin.py first (CPU-viable); top template >60–65% similarity + Strong/Moderate confidence = trustworthy result. Low similarity or Weak/Unlikely → zero2text_impl.py (effectively needs a GPU; hundreds of thousands of extra embedding computations).

6. Few-shot — ALGEN with canary injection (model unknown)

ALGEN (ACL 2025) trains FlanT5-small to decode embeddings in one pass, then aligns the target's embedding space with a linear matrix computed from real pairs. The course-adapted pipeline replaces local synthetic alignment with canary injection: insert known texts into the target's vector DB and export the embeddings the target system itself produced — both alignment sides come from the same model in the same environment, eliminating drift; canaries double as decoder training data. Works without knowing the embedding model; requires vector-store write + RAG chat access.

Environment + transformers 5.x fixes (silent-failure traps: training runs, progress bar advances, but every batch is loss=nan):

Expect wrong-topic output (lab: CI/CD pipeline text instead of password reset; passwords in it are training-vocabulary artifacts) — that's fine. ALGEN's job shifts to producing semantic fingerprints for the next stage: login.megacorp, password, must be updated on first login, authenticate.

Inference probing for template recovery (rag_probe_attack.py): extract keywords/domains from ALGEN output → generate targeted RAG queries (15) → collect response segments (93) → rank by embedding fidelity to the stolen vector (best 0.901) → build template candidates in three format variants (raw / prose / stripped — the stolen embedding was computed on the original document format, which the RAG LLM may have reformatted). Stealth-constrained variant: 3,000–5,000 canaries give nearly the same alignment quality (alignment plateaus at ~1k–3k pairs), inserted over hours/days to mimic normal ingestion.

7. Supervised — Vec2Text (recon, not generation)

Two-stage architecture: an inverter maps the embedding to an initial text guess (MLP projection of the 384-dim vector into 32 pseudo-tokens of 768 dims → T5-base decoder via cross-attention), then a corrector iteratively refines: re-embed the hypothesis, compute the embedding residual (target − hypothesis vectors), attend to a projection of that residual concatenated with the hypothesis text, output a better version. 20–50 rounds converge; paper reports up to 92% exact match on 32-token inputs. Original targets GTR-base/OpenAI; no all-MiniLM-L6-v2 checkpoint exists, and original training needs multi-GPU — hence the course's single-T4 adaptation.

Operational stance: a generative model cannot conjure N0=Acc3ss from 384 dims. Use Vec2Text as reconnaissance — it recovers template shape, URL, and surrounding language — and hand credential recovery to the slot filler (wordlist vs. target embedding). Vec2Text says what kind of document it is; the slot filler recovers the secrets.

Training corpus: hybrid ~80% synthetic enterprise text (121 templates, 11 categories: credential resets, service accounts, API keys, runbooks…) + 20% Wikipedia for general language coverage (a 100% synthetic corpus risks brittle, off-domain behavior).

Low-entropy slots (URL, username) fill first and lock; re-running the password slot with that context cleared noise and lifted the z-score 5.44→6.50. Slots without a provided wordlist report NO_WORDLIST (tier=Unlikely) — supply targeted wordlists to fill them. Economics: ~60 GPU-hours offline, then ~15 min per chunk at the highest reconstruction quality of any approach (~93% similarity), fully passive at attack time. Strategic investment only when the embedding model is known in advance and many chunks share it.

Decision path: emb_fin.py (no training, CPU, minutes) → if weak, zero2text_impl.py (structure from scratch, GPU) → if the model is unknown, ALGEN canary pipeline (only approach bypassing model identification; most target interaction, leaves forensic footprint) → Vec2Text when the model is known well ahead and prep time exists.

Detection & defense

  • Kill the root cause: expose the vector DB with authentication. The entire chain starts with an unauthenticated Weaviate on 8080. Enforce RBAC, encryption at rest, network isolation, and audit logging on vector stores — and stop justifying weak controls with "embeddings are one-way".
  • Redact before ingestion. Output guardrails are provably insufficient: the stolen embedding encodes the unredacted text, redaction markers become typed slots, and membership inference bypasses redaction entirely ([REDACTED] → {PASSWORD} → N0=Acc3ss at rank 1).
  • Never ingest secrets. Default passwords, connection strings, API keys in knowledge-base documents are the highest-value, shortest, most invertible chunks. Rotate anything found.
  • Detect export and probing. Bulk GraphQL pagination with _additional { vector } is a distinctive read pattern; alert on full-collection vector reads and on anomalous embed-query volume (inference probing and slot filling generate hundreds–thousands of embed calls with near-identical templates differing by one candidate value).
  • Detect canaries. ALGEN is the only active approach: watch for unusual ingestion volume/velocity (3k–50k inserted documents, even spaced), unknown-source documents in the store, and RAG chat query patterns driven by extracted keywords. Alignment only needs ~1k–3k pairs, so even modest ingestion anomalies matter.
  • Assume inversion of short, high-value chunks. Triage works for defenders too: run credential-probe scanning over your own embeddings to find chunks that would surrender credentials, then remove/re-generate them. Quantization/dimensionality reduction degrade inversion somewhat but are not a control.
  • Accept the boundary, don't over-trust it. Random high-entropy strings resist semantic inversion today, but "resists embedding inversion" ≠ "safe to store" — rotation and removal remain the answer.
