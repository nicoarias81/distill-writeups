FFUF: los tesoros escondidos de la herramienta

Resumen

Joona Hoikkala (handle @joohoi, head of security testing en Visma y autor de buena parte del código de ffuf) dedicó una lightning talk a las funcionalidades poco conocidas de la herramienta. La premisa: casi todo el mundo usa ffuf para content discovery, fuzzing de APIs o enumeración de virtual hosts, pero el nivel siguiente está en combinar funciones que casi nadie conoce —algunas ni siquiera documentadas hasta esta presentación—. Seis gemas, una tras otra, con demos en vivo.

Las seis gemas

1. Replay proxy

Cada match que ffuf encuentra se reenvía a un proxy (Burp, ZAP, Caido). Un flag (-replay-proxy) y cada resultado aparece al instante en el repeater para investigarlo a mano. La variante potente no es de la herramienta sino de uso: SSH reverse port forwarding. Se hace la conexión SSH al VPS y se reenvía el puerto local de Burp (8080) a un puerto remoto (8282); ffuf corre en el VPS con replay-proxy apuntando a 8282, y los matches aparecen en el Burp local. Resultado: aunque la conexión de internet local sea mala, se aprovecha el ancho de banda del VPS para escaneos grandes sin perder la visibilidad local.

2. Payload encoder

Un año en el código, documentado solo en un pull request cerrado del repositorio: se puede encodar cada entrada de la wordlist al vuelo con -enc Word:b64encode, y encadenar transformaciones (mayúsculas primero, Base64 después). Hay una herramienta standalone con la misma lógica: PEMCode, en github.com/ffuf/pemcode.

3. FFUF hash

Otra keyword que se puede insertar en cualquier posición del request: genera un hash único por payload o combinación de payloads. Pensada para out-of-band: se apunta a un subdominio de Burp Collaborator (o InteractSH, o DNS propio) con el hash adelante, se fuzzea, y cuando el callback llegue —minutos, días, semanas, incluso años después— el hash revela exactamente qué request lo disparó.

El detalle técnico fino: ffuf no guarda los requests salientes (llenaría el disco). Guarda la configuración de la ejecución, y el hash incluye la posición del payload dentro de esa configuración. Al buscar el hash, ffuf reabre la wordlist desde su ubicación original y reconstruye el request exacto de hace un año, sin llenar el disco duro. La contrapartida: la wordlist tiene que seguir en su lugar original.

4. Scraper

Extracción de datos de las respuestas con selectores tipo jQuery o regex, definidos en archivos JSON agrupados por nombre (en macOS: ~/Library/Application Support/ffuf/scraper/; en Linux: ~/.config/ffuf/scraper/). Con only_match: true scrapea solo cuando ffuf ya matcheó; con false, actúa como librería de vulnerabilidades propia: si el fingerprint de una librería vulnerable aparece —aunque venga en un 404 filtrado por defecto— el resultado se entrega igual. Los archivos pueden marcarse active: true para estar siempre activos sin flags en la línea de comandos, y cada grupo admite tantas reglas como se quiera.

5. FFUFRC

El archivo de configuración por defecto: cualquier flag se puede pre-cargar. La demo práctica: cambiar el user agent (por defecto ffuf/v1.x, con lo que los WAF lo detectan al instante) por el de un navegador real. Mismo escaneo, misma wordlist, mismos sitios: los títulos que antes devolvían páginas de Cloudflare y de un WAF aparecen limpios.

6. JSON output + jq

-json -s produce JSON lines (un objeto por línea, sin banner ni barra de progreso): salida para computadoras, no para humanos. Combinado con jq se arma una cadena de automatización que extrae cualquier campo —títulos HTML, resultados de scraper— del flujo de ffuf.

    A -- -json -s --> C[jq]
    C --> D[Automatización]
    A -- FFUF hash --> E[OOB: Collaborator / InteractSH]

Conclusiones

  • Las funciones más potentes de ffuf no están en la superficie: replay proxy, encoder, hash, scraper y RC convierten un fuzzer en el centro de una cadena de trabajo completa.
  • El patrón recurring es el mismo: ffuf genera datos estructurados y el resto de la cadena (Burp, jq, scripts) los consume.
  • La lección de infraestructura importa tanto como la herramienta: correr ffuf donde hay ancho de banda y traer los resultados a donde hay contexto, con un túnel SSH invertido, resuelve el cuello de botella más común del fuzzing remoto.
  • La documentación incompleta se arregla en público: el encoder y el scraper existían sin documentación y esta presentación fue su primera exposición formal.
