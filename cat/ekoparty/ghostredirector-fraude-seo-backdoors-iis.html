GhostRedirector: fraude SEO sobre servidores Windows con exploits "potato" y un módulo IIS

Resumen

GhostRedirector es un actor de amenazas que compromete servidores Windows para hacer fraude SEO: intercepta las respuestas que el servidor le devuelve al bot de Google y las reemplaza por contenido que mejora el posicionamiento de sitios de interés del atacante, como plataformas de apuestas. La campaña, documentada por ESET desde abril de 2025 pero activa por lo menos desde agosto de 2024 según muestras subidas a VirusTotal, dejó más de 65 víctimas a nivel mundial — Brasil y Tailandia como focos, con verticales de transporte, salud, educación, retail y aseguradoras.

El nombre "fraude SEO" subestima el problema: no es solo la reputación del sitio comprometido, sino la distorsión de resultados de búsqueda en beneficio económico de terceros. El análisis técnico recorre el arsenal completo — exploits potato para escalar privilegios, un malware que despliega webshells, un backdoor pasivo que vive de las APIs HTTP de Windows y un módulo nativo de IIS que hace la manipulación en el pipeline de cada solicitud.

Conceptos base: el pipeline de IIS y la ventana de ataque del SEO

El terreno de juego es IIS, el servidor web de Microsoft para Windows, con arquitectura modular que soporta FTP, SMTP, HTTP y HTTPS. La clave está en los módulos nativos — DLLs en C++ — que se integran al pipeline de procesamiento de una solicitud HTTP: con métodos como beginRequest pueden abrir y manipular una request entrante, y con onSendResponse modificar la respuesta que el servidor está por devolver. IIS además agrupa aplicaciones en Application Pools, un detalle que el malware explota para decidir dónde instalar sus webshells.

El fraude SEO entra cuando un componente malicioso intercepta la respuesta dirigida al motor de búsqueda y la altera. El esquema: llega una request de Googlebot al servidor comprometido, el malware consulta a su servidor de comando y control, obtiene el contenido a inyectar y lo mete en la respuesta oficial — o la reemplaza directamente. El efecto es quirúrgico: solo el bot de Google ve el cambio. Cualquier persona que escriba la URL directamente navega por el sitio limpio, sin sospechar nada.

Victimología: quién cae y cómo

Más de 65 víctimas — cada una un servidor — distribuidas mundialmente, con concentración en Brasil y Tailandia y presencia en Filipinas, India, Finlandia, Países Bajos, Portugal, Canadá y Estados Unidos. Un matiz interesante: varias víctimas estadounidenses son servidores físicos con sitios web en portugués o vietnamita, lo que sugiere que empresas de esos países contratan infraestructura en el norte.

La puerta de entrada más frecuente en la telemetría es una vulnerabilidad de SQL Injection en el sitio web: input mal sanitizado que permite romper la sintaxis SQL y, en este caso, ejecutar comandos de PowerShell que descargan la batería de malware desde un sitio controlado por el actor.

Los exploits "potato"

Ocho ejecutables en .NET, con código fuertemente basado en dos exploits clásicos para escalar privilegios — Bad Potato y God Potato — que manipulan el token de acceso de Windows para ejecutar código con permisos de administrador. No son exploits nuevos, pero siguen funcionando. La comparación con la prueba de concepto pública es contundente: el malware conservó hasta los strings de inicialización y de explotación satisfactoria; solo agregaron la creación del usuario malicioso al final del flujo.

Los usuarios creados respondían a tres nombres — MySQL ServiceX, X2 o Admin — y todos iban al grupo de administradores. En algunos casos la contraseña contenía el string "huang", palabra china que significa amarillo. Todo el código venía ofuscado con .NET Reactor (cifrado de strings, control flow flattening, renombrado de clases y métodos, carga dinámica de código invisible a dnSpy) y con anti-debugging y anti-disassembly. Y, detalle nada menor, las muestras estaban firmadas digitalmente con un certificado de la empresa china Trust Asia — segundo indicador de origen, aunque no se sabe si el certificado fue obtenido o robado.

Zoomput, el instalador

Malware en .NET, firmado con el mismo certificado, cuya función es recolectar información de los sitios web del servidor — nombre, ruta de instalación, bindings con IP — y guardarla en un archivo de log que deja en la misma ruta de ejecución, un comportamiento inusual ya que lo habitual es exfiltrar al C2 (con webshells o con Rungan activo hay vías para extraerlo después).

Su lógica de despliegue usa los Application Pools: enumera todos los sitios registrados en IIS, verifica si la ruta física existe — un sitio puede estar frenado en IIS pero eliminado del disco, y en ese caso solo queda en el log — y sobre los sitios vivos instala webshells en PHP, ASP o JS, con nombres y extensiones tomados de una lista embebida y los archivos guardados sin cifrar en sus recursos. Un toque de evasión notable: al crear cada webshell copia la fecha de otro archivo del mismo directorio para sus campos de creación, modificación y último acceso, de modo que el administrador que revisa la carpeta no vea un archivo de 2025 entre archivos de 2017. Otro rastro de origen: el archivo de log usa como separador tres caracteres chinos que significan "línea divisoria".

Rungan, el backdoor pasivo

DLL en C++ para 64 bits con strings cifradas en AES modo CBC — código cuya implementación coincide con un repositorio público con README en chino. A diferencia de un RAT tradicional, no se comunica con ningún C2: queda loopeando a la espera de que el operador se conecte primero. Su truco técnico es la HTTP Server API de Windows, un conjunto de APIs para establecer comunicación HTTP que es independiente de IIS — funciona aunque el servidor corra Apache Tomcat.

Rungan registra una URL hardcodeada (sin cifrar) en el listado de URLs del servidor — visible con netsh en PowerShell — y queda a la escucha. Cuando llega una request que coincide, valida parámetros hardcodeados y ejecuta: crear un usuario en el grupo de administradores (usuario, contraseña y grupo viajan en el body, y la respuesta es "success"), listar el contenido de una carpeta, registrar otra URL como listener adicional o ejecutar comandos arbitrarios — un parámetro action con valor CMD indica que el comando viene en el body.

Gamgen, el módulo que hace el fraude

DLL en C++ (versiones de 32 y 64 bits) que se integra como módulo nativo de IIS — el componente del título. Su lógica vive en onBeginRequest y aplica una cascada de validaciones antes de actuar: el user agent debe ser Googlebot o el referer google.com; la request no debe ser POST (busca GETs); no debe ser una imagen, hoja de estilos o JS, porque romper la parte gráfica del sitio no le interesa; y la URL debe contener el string "android" o coincidir con alguna de seis o siete expresiones regulares orientadas a contenido mobile — play, article, detail, iOS.

Cumplidas las condiciones, hace una request al dominio del C2 hardcodeado con un user agent propio, recibe la respuesta en base64 y la inyecta en la respuesta legítima del servidor. El C2 estaba muerto durante la investigación, así que el contenido final se reconstruyó pivotando en VirusTotal: del dominio a IPs relacionadas, a otros dominios, más IPs, más dominios, hasta aparecer capturas de imágenes en portugués — "los mejores de Brasil, plataforma de apuestas online" — que delatan el objetivo del posicionamiento fraudulento.

Técnicas y herramientas mencionadas

  • IIS y módulos nativos — DLLs en C++ integradas al pipeline HTTP con beginRequest/onSendResponse; Application Pools para agrupar aplicaciones.
  • Fraude SEO — inyección de contenido en respuestas dirigidas al bot de Google para mejorar el posicionamiento de sitios del atacante.
  • SQL Injection + PowerShell — vector de acceso inicial y descarga del arsenal.
  • Bad Potato / God Potato — exploits .NET de escalada de privilegios por manipulación de tokens de acceso.
  • .NET Reactor — ofuscación con cifrado de strings, control flow flattening, carga dinámica de código y anti-debugging.
  • Zoomput — instalador .NET que enumera sitios de IIS, instala webshells (PHP/ASP/JS) en sitios activos y genera un log de información; copia fechas de archivos vecinos como táctica de evasión.
  • Rungan — backdoor pasivo en C++ 64 bits; escucha en una URL registrada vía HTTP Server API de Windows; crea usuarios, lista carpetas, ejecuta comandos y registra URLs adicionales.
  • Gamgen — módulo nativo de IIS que filtra requests de Googlebot y les inyecta contenido del C2 en base64.
  • VirusTotal como herramienta de pivoting — reconstrucción del contenido objetivo del fraude a partir de relaciones de dominios e IPs.
  • Certificado digital Trust Asia — firma de las muestras, empresa china; indicador de alineación con China junto a strings y comentarios en chino.
  • DragonRank (Cisco Talos) — actor previo documentado en 2024 con la misma modalidad: fraude SEO alineado con China.

Conclusiones

  • GhostRedirector es un actor de amenazas con motivación financiera directa: comprometer servidores para boostear el posicionamiento SEO de sitios de apuestas, un fraude que distorsiona los resultados de búsqueda para los usuarios finales.
  • El kit es pragmático, no sofisticado: exploits potato viejos y públicos que siguen funcionando, código reutilizado de repositorios públicos con sus strings intactos, y una cadena SQL Injection → PowerShell → arsenal.
  • La evasión está en los detalles: malware firmado con un certificado de apariencia legítima, ofuscación con .NET Reactor, webshells que heredan las fechas de archivos vecinos, y manipulación visible solo para el bot de Google.
  • La combinación de indicadores — contraseñas con "huang", strings y comentarios en chino, certificado de Trust Asia, paralelo con DragonRank — apunta a un ecosistema de amenazas de fraude SEO alineado con China que recién empieza a documentarse.
  • Para los administradores de servidores Windows: parchear SQL Injection, revisar módulos nativos de IIS, auditar usuarios del grupo de administradores y verificar el listado de URLs registradas son verificaciones concretas y baratas frente a este actor.
