Hackear la inteligencia artificial que detecta ransomware

Resumen

Los modelos de machine learning se usan cada vez más para detectar malware, pero esos mismos modelos tienen una debilidad estructural: parten de datos y predicen con base en un error, y ese error se puede explotar. Este trabajo muestra el ciclo completo: cómo se construye un modelo de defensa que clasifica tráfico de ransomware con alta precisión, cómo un atacante usa deep reinforcement learning para generar muestras adversarias que lo engañan, y cómo reentrenar el modelo con esas muestras lo vuelve mucho más robusto.

El proyecto — documentado en un libro gratuito en español sobre adversarial machine learning — combina un laboratorio de malware con red aislada y simulación de internet, un clasificador Random Forest entrenado sobre paquetes UDP, y un agente de deep reinforcement learning que perturba el tráfico hasta que el defensor deja de verlo como malware. El resultado: un modelo que pasaba de detectar el 0% del tráfico adversario pasa a reconocer en promedio el 85% tras el adversarial training.

Cualquier modelo de machine learning es hackeable

La premisa de partida es simple: todo modelo de clasificación dibuja una frontera de decisión, y basta una perturbación mínima — una máscara, una matriz de números aplicada a la entrada — para que la entrada salte de un lado a otro de esa frontera sin que un humano note la diferencia. Se vio en vivo con un sistema biométrico de detección de rostros falsos: una imagen etiquetada como falsa con 100% de confianza pasa a clasificarse como real tras aplicar una máscara. El famoso ejemplo del panda que se convierte en gibón ante un clasificador de imágenes es la ilustración clásica del mismo fenómeno.

Esto se conecta con el hacking tradicional: se pueden romper la integridad, la disponibilidad y la privacidad de un sistema de IA igual que en cualquier otro sistema. Y no es un área cerrada: OWASP ya publicó un top 10 de vulnerabilidades para large language models, con ejemplos como el prompt injection — logrando que un modelo que se niega a entregar código de ransomware lo entregue en Python tras una frase bien colocada.

El laboratorio: capturar tráfico de ransomware de forma controlada

Para tener datos reales de ransomware sin riesgo, el montón de laboratorio es una red privada virtual sin salida a internet ni conexión con el host. Dos máquinas virtuales:

  • Máquina de análisis (Ubuntu): corre InetSim (que simula las respuestas de internet en los puertos 80 y 443), un proxy que redirige el tráfico y Wireshark para capturarlo.
  • Máquina víctima (Windows): corre las muestras de ransomware, con el DNS apuntando a la máquina de análisis.

El ransomware se ejecuta, cifra archivos y pide el rescate en Bitcoin como siempre, pero sus conexiones reciben respuestas genéricas del simulador. De ese entorno salen las capturas de tráfico malware reales que alimentan todo el resto del proyecto.

El modelo de defensa

El dataset es el USTC-TFC2016: 14 capturas de tráfico benigno y 10 de tráfico malware, alrededor de un millón de registros y más de 20 GB. La decisión técnica clave: quedarse solo con el campo de paquetes UDP, recortado a los primeros 1024 bytes. El estado del arte muestra que las diferencias entre tráfico benigno y malware se concentran entre los bytes 750 y 1250, así que ese recorte es suficiente para discriminar.

Con ese feature extraction (capturas .pcap → CSV) se probaron Naive Bayes, Random Forest y DeepMal. El mejor modelo fue Random Forest, con una precisión de 0.8371 — los falsos positivos visibles en la matriz de confusión se explican por el desbalance entre datos benignos y malware del entrenamiento.

El ataque: deep reinforcement learning en modo black box

Sobre ese modelo de defensa — que funciona — se plantea la pregunta del atacante: ¿qué comportamiento debo cambiar para que no me detecte? El enfoque es black box, sin ningún acceso al algoritmo, datos de entrenamiento o formato de entrada del defensor, que es el escenario realista de un atacante.

El agente de deep reinforcement learning recibe el CSV de tráfico malware capturado y, mediante un sistema de recompensas, aprende a modificar los primeros 1024 bytes hasta que el modelo de defensa los clasifica como tráfico benigno. Los hiperparámetros elegidos tras experimentar: learning rate de 0.0001, gamma de 0.9, epsilon de 1, entrenamiento durante 1000 épocas. Los discriminadores usados para generar los datos adversarios fueron el propio modelo de defensa (DeepMal) y el Random Forest. Cuando el agente logra engañar al defensor, el resultado se guarda como muestra adversaria.

El contragolpe: adversarial training

Las muestras adversarias se mezclan con las originales (80% entrenamiento, 20% validación) y el modelo de defensa se reentrena — con una decisión importante: las muestras adversarias se pasan con su etiqueta correcta de malware, no con la que el atacante quería que creyeran. El modelo aprende a diferenciar ese comportamiento.

Resultados: la precisión sube de 0.8371 a 0.8448, con menos falsos positivos y falsos negativos. Pero lo relevante es la validación cruzada (k=5) sobre los datos adversarios: el modelo pasó de reconocer el 0% del tráfico adversario a reconocer en promedio el 85%. El adversarial training, aplicado en un ciclo continuo — igual que el trabajo de un pentester — robustece el modelo de forma medible.

Técnicas y herramientas mencionadas

  • Adversarial machine learning: campo que estudia entradas sintetizadas para forzar resultados erróneos en modelos de clasificación.
  • Deep Reinforcement Learning: redes neuronales profundas que aproximan funciones de valor y políticas; usado para perturbar el tráfico malware.
  • Random Forest / Naive Bayes / DeepMal: algoritmos evaluados para el modelo de defensa; ganó Random Forest.
  • USTC-TFC2016: dataset de tráfico benigno y malware (~1 millón de registros, 20+ GB).
  • InetSim, Wireshark, proxy: laboratorio de análisis con internet simulado y captura completa del tráfico.
  • Prompt injection / OWASP LLM Top 10: vulnerabilidades de los modelos generativos de lenguaje.
  • Adversarial training: reentrenamiento con muestras adversarias etiquetadas correctamente; mejora la robustez del 0% al 85% de detección.

Recomendaciones de desarrollo seguro para modelos de ML

El proyecto deja cuatro medidas concretas para proteger modelos de machine learning en producción:

  1. Mantener privadas las entradas del modelo, para que un atacante no pueda enumerar ni explorar cómo recibe sus datos.
  2. Limitar el acceso a los datos de entrenamiento: quien los obtiene deduce estructura, tipos y comportamiento.
  3. Hacer adversarial training siempre que sea posible — es la medida con efecto demostrado.
  4. Dificultar el reconocimiento: limitar el número de consultas al modelo, ocultar información sensible de los logs de error y cifrar los datos en tránsito cuando sean sensibles.

Como trabajo futuro: ampliar las columnas de entrada más allá de los paquetes UDP, explorar perturbaciones variando el tamaño de los datos (no solo los primeros 1024 bytes) y continuar el entrenamiento desde un enfoque black box, que es el más realista.

Conclusiones

  • Todo modelo de machine learning es hackeable porque predice con base en un error, y ese error se explota con perturbaciones imperceptibles.
  • Un laboratorio controlado (red aislada + internet simulado) permite capturar tráfico de ransomware real de forma segura para entrenar y atacar modelos.
  • Para detectar malware por sus paquetes UDP, Random Forest fue el mejor algoritmo del conjunto probado.
  • El adversarial training con etiquetas correctas convierte las muestras de ataque en material de defensa: del 0% al 85% de reconocimiento del tráfico adversario.
  • La seguridad de un modelo no es un estado final sino un ciclo: atacar, reentrenar, validar, y volver a empezar.
