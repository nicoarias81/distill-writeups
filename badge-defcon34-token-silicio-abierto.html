El badge de DEF CON 34: un token de seguridad con chip de silicio open source

Fuente: «DEF CON 34 - Video Team - DEF CON 34 Badge - Bunnie Huang» · ver el video original

Resumen

Para DEF CON 34, el equipo del badge quiso romper con la idea del badge como pieza de arte que se cuelga en la pared y se olvida: el objetivo era algo útil a diario. Para una audiencia de seguridad, la elección natural fue un token de seguridad por hardware. El módulo plástico central del badge es desmontable y funciona como hardware security token: soporta login FIDO2, códigos TOTP rodantes de seis dígitos y almacenamiento de contraseñas. Se saca del badge, uno se cuelga el badge y se lleva el token a todas partes.

La particularidad es que el creador del badge, Bunnie Huang, no solo diseñó la placa: diseñó el chip de silicio que va dentro. Para fabricarlo tuvo que fundar una empresa, Baochip (de ahí el nombre impreso en el badge), que hace el soft launch del producto con este badge. Y la decisión estructural de todo el proyecto es que nada es closed source: el chip es silicio open source —se puede descargar la mayor parte de su diseño, revisarlo, buscar bugs e intentar parchearlos—, la placa de circuito es open source, el bootloader es open source, las aplicaciones son open source. "OS everything": transparencia desde la capa de aplicación hasta el hardware que uno tiene entre las manos.

Transparencia hasta los transistores

Como Bunnie fabrica el chip, puede empaquetarlo de forma que, si se le apunta con luz infrarroja, se ven los transistores reales del interior. Eso permite verificar que el chip dentro del paquete negro es realmente el Baochip y no otro. La transparencia llega así a un nivel mucho más profundo que una certificación o un sello de seguridad: el argumento central es que uno no debería confiar en que "un tipo como él" le diga que el dispositivo es seguro, sino verificarlo por sí mismo con todo el material puesto a disposición.

La motivación viene de la experiencia de Bunnie en ambos lados —red team y blue team, hackeando hardware—. Atacar el hardware físico es factible pero no escala: hay que robar cada badge uno por uno para extraerle las claves. Lo que escala es la cadena de suministro: hackear el firmware de un producto comprado, pegar la etiqueta y devolverlo para que otro lo compre; o entrar directamente en las fábricas e instalar el firmware comprometido dentro de la propia fábrica o modificar los chips. La transparencia de extremo a extremo ataca precisamente ese problema de supply chain: permite verificar que el chip es el que uno cree, sin depender de certificaciones ni precintos.

"God mode debugging" y el B10

Tener el código fuente del hardware no sirve solo para auditarlo: transforma el proceso de desarrollo. Con el source del chip se puede hacer lo que Bunnie llama "god mode debugging": poner el código dentro de la simulación y avanzar y retroceder en el tiempo, entrar en la CPU y ver qué pasa por su cabeza —el timing de las instrucciones, lo que atraviesa el banco de registros, cuándo se retiran las instrucciones—. Con la simulación corriendo, no hay bug que no se pueda encontrar.

El chip incluye el B10, un bloque comparable al PIO del Raspberry Pi pero open source —"un kart para hackers"— con un núcleo PicoRV32 de 700 MHz sobre el que se puede cargar código, hackear y manipular las IO. Para bajar la barrera de entrada, hay un paquete preparado que permite ejecutar el código del B10 como simulador dentro de un contenedor Docker, sin necesitar conocimientos profundos de hardware. Y para quien ni eso: se le puede tirar el material a un modelo de IA, que sabe exactamente qué hacer con él y produce código de mejor calidad por tener una simulación como ground truth contra la que validar.

Comunidad y futuro

Se fabricaron alrededor de 30.000 badges, y es una pre-alpha run del chip Baochip. En pocas horas de congreso la comunidad ya hacía de todo: bad Apple corriendo en el badge, alguien trabajando en un port de Doom, un enlace a "algún Linux" aparecido en línea. Para Bunnie ese es exactamente el punto: escalarse a hackear como uno quiera.

Los planes futuros: los chips estarán disponibles para que cualquiera los use en sus propios productos (open source, por definición), y el módulo central se convertirá en un producto standalone para quien quiera un dispositivo con transparencia y verificabilidad de primer nivel, previsto para más adelante en el año. El diseño exterior del badge es obra de los diseñadores (Cheezo y equipo), una colaboración entre utilidad y arte: la utilidad del token de seguridad con el arte que siempre definió a los badges de DEF CON.

Técnicas y herramientas mencionadas

  • Hardware security token desmontable: FIDO2, TOTP de 6 dígitos y almacenamiento de contraseñas.
  • Baochip: chip de silicio open source diseñado por Bunnie Huang; empresa fundada para fabricarlo.
  • Transparencia por capas: silicon open source, PCB open source, bootloader open source, aplicaciones open source.
  • Verificación óptica: empaquetado que permite ver los transistores con luz infrarroja para confirmar la identidad del chip.
  • God mode debugging: simulación del hardware con viaje temporal e inspección del pipeline de la CPU.
  • B10: bloque estilo PIO open source con núcleo PicoRV32 a 700 MHz.
  • Simulador del B10 en Docker: paquete para probar el firmware sin hardware físico.
  • Amenaza de supply chain: firmware comprometido vía devoluciones de producto o acceso a fábricas como el vector que escala.

Conclusiones

  • El badge de DEF CON 34 convierte el objeto coleccionable en un token de seguridad FIDO2/TOTP útil a diario, con un chip de silicio diseñado ad hoc (Baochip) en su soft launch.
  • La propuesta es transparencia total: cada capa del stack, del software al silicio, es open source y verificable por el usuario, desplazando la confianza de las certificaciones hacia la verificación personal.
  • El argumento de seguridad se apoya en el modelo de amenaza correcto: el ataque físico individual no escala; la cadena de suministro sí, y solo la transparencia verificable lo contrarresta.
  • El acceso al source del hardware habilita simulación con "god mode debugging", que convierte la búsqueda de bugs del chip en un problema tractable, y el B10 con paquete Docker baja la barrera para hackers de software.
  • Con ~30.000 unidades, es una pre-alpha del chip: la comunidad ya respondió con ports y hacks en las primeras horas, y el chip y el módulo standalone estarán disponibles como producto.
