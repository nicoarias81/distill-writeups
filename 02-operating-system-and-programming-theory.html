Objective

Theory-only module (no exercises, no course videos): the programming-language landscape and the Windows concepts that the rest of PEN-300 leans on — language levels, OOP vocabulary, WOW64, Win32 APIs, and the registry. The course's stance on the classic "do I need to program?" question: formal programming education is not required, but broad language knowledge pays off directly in understanding software vulnerabilities and OS concepts.

Programming theory

Language levels

  • Compiled vs interpreted: compiled code is converted to binary before execution; interpreted scripts are parsed line-by-line at run time. (Course note: this framing ignores JIT/optimization subtleties — deliberately, as they rarely matter to pentesters.)
  • Low level → opcodes: the CPU acts on opcodes (binary values mapped to specific actions); opcodes render as assembly for human readability. The x86 architecture (and ARM on most smartphones/tablets) defines which opcodes are valid and what they do. OS kernels and browsers have assembly elements for low overhead; pentesters rarely write it but benefit from reading it for security-product bypasses and advanced attacks.
  • C / C++: C is human-readable but still low-level; C++ spans both — full C feature set plus inline assembly, plus OOP (classes/objects).
  • Unmanaged vs managed: C/C++ compile to opcodes executed directly by the CPU and must do their own memory management (unmanaged code). Java/C# compile to bytecode run by a virtual machine (managed code) — the VM provides memory management that can prevent bug classes like buffer overflows. Java → JVM (part of the JRE); C# → CLR (part of .NET). Browsers run JS in a VM too, with JIT compilation to native code for hot loops.
  • Portability note: Java is OS-independent by design; C# was historically Windows-bound until .NET Core brought it to Linux/macOS.
  • High-level scripting languages (Python, JavaScript, PowerShell) are OOP-based.

OOP concepts (vocabulary used throughout the course)

  • Class = template for objects; holds variables (data) and methods (actions on them).
  • Objects are instantiated from a class via a constructor — a special method named after the class that initializes instance variables.
  • Access modifiers: public (callable/reachable from inside and outside the class) vs private (inside the class only). In the module's MyClass example, any code can call the MyClass(int aNumber) constructor, but outside code must go through the public getNumber() method to read the private myNumber field.
public class MyClass
{
    private int myNumber;

    // constructor
    public MyClass(int aNumber)
    {
        this.myNumber = aNumber;
    }

    public getNumber()
    {
      return myNumber;
    }
}

These terms matter as soon as custom attack tooling is written and when reverse-engineering high-level code.

Windows concepts

Windows On Windows 64 (WOW64)

  • Lets 64-bit Windows run 32-bit applications with almost no efficiency loss (64-bit Linux does not natively run 32-bit binaries — worth knowing when choosing shellcode runners).
  • Implemented with four 64-bit libraries: Ntdll.dll, Wow64.dll, Wow64Win.dll, Wow64Cpu.dll, which emulate 32-bit execution and translate between the app and the kernel.
  • Filesystem split: on 64-bit Windows, 64-bit binaries/DLLs live in C:\Windows\System32 while 32-bit ones live in C:\Windows\SysWOW64 (the counterintuitive naming — SysWOW64 holds 32-bit — trips people up constantly).
  • Why it matters operationally: target bitness dictates the shellcode and compiled payloads we can use.

Win32 APIs

  • Pre-built OS functionality documented with C-style types and prototypes, invocable from many languages (the course uses them from C#, PowerShell, etc. throughout).
  • Example prototype — GetUserNameA (exported by Advapi32.dll, returns the executing user's name):
BOOL GetUserNameA(
  LPSTR   lpBuffer,
  LPDWORD pcbBuffer
);

LPSTR = pointer to a character array (output buffer), LPDWORD = pointer to a 32-bit unsigned integer (buffer size in/out), BOOL return. - Two details to check on every API call: 1. Bitness — some argument types and sizes differ between 32- and 64-bit processes. 2. ASCII vs Unicode ("wide") — most APIs exist in two versions; the suffix picks the character set. GetUserNameA takes LPSTR (ANSI), GetUserNameW takes LPWSTR (Unicode/UTF-16).

BOOL GetUserNameW(
  LPWSTR  lpBuffer,
  LPDWORD pcbBuffer
);

Windows Registry

  • The OS's "global variables": a database of keys with associated values, hierarchically organized in subkeys, rooted in hives. HKEY_CURRENT_USER (HKCU) holds per-user data; HKEY_LOCAL_MACHINE (HKLM) holds OS-wide data.
  • Privilege split with direct offensive value: HKCU is writable by the current user; HKLM modifications require administrative privileges — persistence/evasion edits are scoped by which hive you can touch.
  • Each hive carries a Wow6432Node duplicate section storing 32-bit application settings (the registry-side mirror of WOW64).
  • Access is programmatic (Win32 APIs) or via regedit; later modules abuse the registry for reconnaissance, attack improvement, and evasion.
